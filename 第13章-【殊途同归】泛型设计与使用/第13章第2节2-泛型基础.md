## 2.1 没有泛型的时代

在Java 5引入泛型之前，集合类只能存储Object类型的引用。这意味着任何对象都可以放入集合，取出时也需要强制类型转换。

```java
List list = new ArrayList();
list.add("hello");
list.add(100); // 编译期不会报错

String s = (String) list.get(0); // 需要强制转换
Integer n = (Integer) list.get(1); // 看似正确，但...
```

上述代码在编译期不会产生任何错误，因为Object是所有类的父类，任何类型都可以赋值给Object引用。但运行时如果转换类型不匹配，就会抛出<font color="red">**ClassCastException**</font>（类转换异常）。

这就是问题的根源：类型错误被推迟到了运行期才发现。

```
    ┌─────────────────────────────────┐
    │   编译期        运行期           │
    │   ┌───┐        ┌───┐            │
    │   │ ✓ │        │ ✗ │            │
    │   └───┘        └───┘            │
    │   类型检查      类型崩溃          │
    └─────────────────────────────────┘
        没有泛型：错误发现太晚
```

## 2.2 泛型的出现

<font color="red">**泛型**</font>（Generics）的核心思想是将类型检查从运行期提前到编译期。通过在集合声明时指定具体类型，编译器就能在代码编译阶段发现类型不匹配的问题。

```java
List<String> list = new ArrayList<>();
list.add("hello");
list.add(100); // ❌ 编译错误！类型不匹配
```

这次，编译器在第二行就直接报错。错误在写代码的瞬间就被捕获，而不是等到程序运行时才崩溃。

## 2.3 类型安全与代码可读性

泛型带来的好处不止于安全。

```java
// 没有泛型
List list = new ArrayList();
list.add("world");
String s = (String) list.get(0); // 必须转换，且可能出错

// 有泛型
List<String> list = new ArrayList<>();
list.add("world");
String s = list.get(0); // 不需要转换，自动返回String
```

泛型让代码更清晰。看到`List<String>`，读者立刻知道这个列表装的是字符串，不需要再去翻阅上下文推断元素类型。取出的元素也不再需要手动转换，编译器已经帮我们完成了类型推导。

## 2.4 泛型在Java体系中的位置

泛型不是独立的语法，而是贯穿Java集合框架的基础设施。`ArrayList`、`HashMap`、`HashSet`等所有集合类都是泛型类。理解泛型，是正确使用集合类的前提。

```
    Object (万能父类)
       │
       ├── String
       ├── Integer
       ├── Animal ───┐
       └── ...       │
                     ▼
          List<Animal>  ← 泛型约束具体类型
```

## 2.5 泛型类

泛型类的定义方式是在类名后添加<font color="red">**类型参数**</font>（Type Parameter），用尖括号`<>`包裹。类型参数是一个占位符，在使用类时由调用方指定具体类型。

```java
public class Box<T> {
    private T item;
    
    public void setItem(T item) {
        this.item = item;
    }
    
    public T getItem() {
        return item;
    }
}
```

`T`是一个类型参数名称，理论上可以任意命名。Java社区约定使用单个大写字母：
- `T` - Type（类型）
- `E` - Element（元素，常用于集合）
- `K` - Key（键）
- `V` - Value（值）
- `N` - Number（数字）

```java
// 使用时指定具体类型
Box<String> stringBox = new Box<>();
stringBox.setItem("hello");
String s = stringBox.getItem(); // 不需要强制转换

Box<Integer> intBox = new Box<>();
intBox.setItem(42);
Integer n = intBox.getItem();
```

类型参数`T`在编译后会被替换为实际类型（如`String`或`Integer`），这个替换过程称为<font color="red">**类型擦除**</font>，后续会详细讨论。

## 2.6 泛型接口

泛型接口的定义方式与泛型类相同：

```java
public interface Generator<T> {
    T generate();
}
```

实现泛型接口时有两种策略。

<font color="red">**策略一：实现类也保持泛型**</font>

```java
public class RandomGenerator<T> implements Generator<T> {
    @Override
    public T generate() {
        // 返回T类型的实例
        return null; // 简化示例
    }
}
```

<font color="red">**策略二：实现类指定具体类型**</font>

```java
public class StringGenerator implements Generator<String> {
    @Override
    public String generate() {
        return "random string";
    }
}
```

## 2.7 泛型方法

泛型方法是指方法自身带有类型参数。类型参数声明在返回类型之前。

```java
public class Util {
    // 泛型方法：类型参数<E>声明在返回类型之前
    public static <E> void printArray(E[] array) {
        for (E element : array) {
            System.out.println(element);
        }
    }
}
```

调用泛型方法时，编译器会根据参数自动推断类型参数：

```java
String[] strings = {"a", "b", "c"};
Util.printArray(strings); // E 推断为 String

Integer[] nums = {1, 2, 3};
Util.printArray(nums); // E 推断为 Integer
```

泛型方法的关键在于：类型参数属于方法，不属于类。一个非泛型类也可以包含泛型方法。

```java
public class PairUtil {
    // 非泛型类中的泛型方法
    public static <K, V> Pair<K, V> createPair(K key, V value) {
        return new Pair<>(key, value);
    }
}
```

## 2.8 类型推断与菱形语法

Java 7引入了<font color="red">**菱形语法**</font>（Diamond Operator），允许在构造器调用时省略右侧的类型参数：

```java
// Java 7之前
Map<String, List<Integer>> map = new HashMap<String, List<Integer>>();

// Java 7之后（菱形语法）
Map<String, List<Integer>> map = new HashMap<>();
```

编译器会根据左侧声明自动推断右侧的泛型参数。这使得代码更加简洁，同时保持类型安全。
