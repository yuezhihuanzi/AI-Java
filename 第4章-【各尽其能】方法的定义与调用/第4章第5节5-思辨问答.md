## 5.1 方法一定要有返回值吗

**问**：老师，书上说「尽量让方法始终有一个返回值」。但我写了很多 void 方法，也没出问题啊？

**答**：你的观察很准确。确实，很多方法用 void 完全没问题。

**问**：那为什么还建议方法要有返回值？

**答**：这要从代码测试和可维护性的角度来理解。

看一个例子：

```java
// 没有返回值的方法
void feed(String foodName) {
    System.out.println("正在喂" + foodName);
}

// 有返回值的方法
boolean feed(String foodName) {
    System.out.println("正在喂" + foodName);
    return true;  // 返回true表示喂食成功
}
```

**问**：第二个方法返回了 true，但好像没什么区别？

**答**：区别在于测试和错误处理。如果方法有返回值，你可以这样测试：

```java
if (cat.feed("鱼")) {
    System.out.println("喂食成功!");
} else {
    System.out.println("喂食失败!");
}
```

但如果方法是 void，你就无法判断这个方法是否执行成功了。

**问**：我明白了。返回值就像是方法给调用者的一个「反馈」。

**答**：没错。特别是在复杂系统中，方法可能会因为各种原因失败（文件不存在、网络断开等）。如果有返回值，就能告诉调用者「我成功了」还是「我失败了」。

> **建议**  
> 这不是绝对规则。对于非常简单的操作（如打印日志），void 完全合适。但对于有业务逻辑的方法，建议返回某种状态标识。

## 5.2 方法签名为什么不包含返回类型

**问**：老师，我一直想不通：为什么 Java 判断方法是否重复，不考虑返回类型？

**答**：这是个好问题。看一个例子：

```java
class Calculator {
    int add(int a, int b) {
        return a + b;
    }
    
    double add(int a, int b) {
        return (double)(a + b);
    }
}
```

**问**：如果返回类型能区分方法，这两个方法就可以共存了？

**答**：理论上可以。但问题来了：当你调用 `add(1, 2)` 时，Java 怎么知道你想调用哪个？

```java
// Java如何判断要调用哪个add方法？
add(1, 2);
```

**问**：啊，确实有歧义！

**答**：所以 Java 的设计者做了一个决定：<font color="red">**方法调用时，只看方法名和参数，不看返回类型**</font>。

> 这样设计虽然限制了方法签名的灵活性，但避免了调用时的歧义。

**问**：那如果我真的想根据返回类型区分方法呢？

**答**：不能用方法重载。你可以用不同的方法名：

```java
int addInt(int a, int b) {
    return a + b;
}

double addDouble(int a, int b) {
    return (double)(a + b);
}
```

**问**：这样就清楚了。调用时明确指定要哪个：

```java
int result1 = addInt(1, 2);
double result2 = addDouble(1, 2);
```

**答**：没错。Java 的设计哲学是：<font color="red">**调用时的明确性比定义时的灵活性更重要**</font>。

## 5.3 形参名真的不重要吗

**问**：老师，书上说形参名不影响方法签名。那形参名可以随便取吗？

**答**：理论上可以，但实际上不应该这样做。

看两段代码：

```java
// 版本1：形参名有意义
double calculatePrice(int quantity, double unitPrice) {
    return quantity * unitPrice;
}

// 版本2：形参名无意义
double calculatePrice(int a, double b) {
    return a * b;
}
```

**问**：功能上完全一样，但版本 1 更容易看懂。

**答**：这就是关键。形参名虽然不影响方法签名，但影响<font color="red">**代码可读性**</font>。

> <font color="red">**形参名是给程序员看的，不是给编译器看的。**</font>

**问**：那形参名应该怎么取？

**答**：有三个原则：

**1. 望文生义**

```java
// 好: 一看就知道是什么
void sendEmail(String emailAddress, String subject)

// 不好: 完全不知道是什么
void sendEmail(String a, String b)
```

**2. 避免缩写**

```java
// 好: 完整拼写
void processOrder(int customerID)

// 不好: 缩写难懂
void processOrder(int custId)
```

**3. 保持一致**

```java
// 好: 同类参数用同名
void buy(String userName, int price)
void sell(String userName, int price)

// 不好: 同样的东西不同名
void buy(String buyer, int price)
void sell(String sellerName, int amount)
```

**问**：所以形参名虽然不影响程序运行，但影响人阅读代码。

**答**：正确。代码是写给人看的，只是顺便让机器执行。
