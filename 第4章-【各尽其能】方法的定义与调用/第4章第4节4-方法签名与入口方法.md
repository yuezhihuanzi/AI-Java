## 4.1 方法签名

所谓<font color="blue">**方法签名**</font>（Method Signature），就是方法的唯一标识，类似身份证。「签名」这个称呼也比较传神，每个方法的签名可以代表自己。

<font color="red">Java 不允许在同一个类中存在相同签名的方法。</font>

看一段示例代码：

```java
class Cat {
    void meow(){
      System.out.println("正在喵喵叫");
    }
    
    void meow(String name){
       System.out.println(name + "正在喵喵叫");
    }
}
```

上述代码有两个同名的方法，但它们参数列表不同。可以吗？

答案是<font color="red">**可以**</font>。可能认为两个同名的方法存在于同一个类中是不合理的。但 Java 并不是这么认为的。

再看下面的代码：

```java
class Cat {
    void meow(){
        System.out.println("正在喵喵叫");
    }
    
    boolean meow(){
        System.out.println("正在喵喵叫");
        return true;
    }
}
```

上面也有两个同名的方法，但它们返回类型不同。可以吗？

答案是<font color="orange">**不可以**</font>，Java 会报错。

这就奇怪了？Java 到底怎么判断可以还是不可以的？

## 4.2 方法签名的构成

Java 判断方法是否重复，并不取决于方法名，而是取决于<font color="red">**方法签名**</font>。方法签名由以下几项构成，<font color="red">**任意一项不同都会被视为不同的方法签名**</font>：

1. **方法名**
2. **参数列表**：
   - 参数列表中参数的数量
   - 参数列表中参数的类型（如 `int`，`String`，`double[]`）

方法名和参数列表，组成了方法的签名。只要两个方法的签名不同，就会被 Java 视为不同的方法，允许同时存在。

### 方法签名不考虑的特征

方法签名<font color="orange">**不考虑**</font>以下特征：

- 方法的返回类型（如 `void`，`int`）
- 访问修饰符（如 `public`，`private`）（后续会讲解）
- 参数名称（如 `(String name)` 中的 `name`）
- 异常列表（如 `throws IOException`）

这里暂时忽略「访问修饰符」和「异常列表」，这两个概念还未讲解。

### 签名判断示例

示例 1：返回类型不同

```java
class Cat {
    void meow(){
        System.out.println("正在喵喵叫");
    }
    
    boolean meow(){
        System.out.println("正在喵喵叫");
        return true;
    }
}
```

上述两个方法是否会被判断为相同方法？

由于上述两个方法签名是相同的，会被认为是相同的方法。<font color="red">**Java 不把返回值类型作为判断依据**</font>，所以返回类型是 `void` 还是 `boolean` 对判断结果没有影响。

示例 2：参数名不同

```java
class Cat {
    void meow(String myName){
      System.out.println("正在喵喵叫");
    }
    
    void meow(String name){
       System.out.println("正在喵喵叫");
    }
}
```

请问上述两个方法的方法签名是否相同？

答案是：它们的方法签名<font color="red">**完全一样**</font>。这看起来有点问题：

- 第 2 行的方法参数名为 `myName`
- 第 5 行的方法参数名为 `name`

之前提到，参数列表是判断方法签名的重要依据。这里参数列表明明是不同的，为什么还是会被认为是相同的方法签名？

原因在于，「参数列表不同」指的是<font color="red">**参数的类型**</font>不能相同，并不是参数名不能相同。上述代码中，虽然一个参数名为 `myName`，一个名为 `name`，但这两个参数的类型都为 `String`。只要参数类型和参数数量相同，就会被认为是相同的参数列表。

<font color="red">**参数名并不作为区分方法签名的依据**</font>，所以它们会被视为相同的方法签名。

示例 3：参数类型不同

```java
class Cat {
    void meow(String name){
      System.out.println("正在喵喵叫");
    }
    
    void meow(char name){
       System.out.println("正在喵喵叫");
    }
}
```

上述两个方法，会被认为方法签名<font color="red">**不同**</font>。因为虽然参数名相同（均为 `name`）、返回类型相同、方法名也相同，但方法参数的类型不同。

Java 只以<font color="red">**参数类型**</font>作为判断依据，并不以参数名作为判断依据。

### 为什么不以参数名作为判断依据

为什么 Java 不以参数名称作为判断依据？

之前谈到过，方法里的参数被称为「形式参数」，它并不是实际参数，参数叫什么名字并不影响方法的最终运行结果。方法的运行结果只受实参的影响。所以形参叫什么并不重要，自然不会作为判断依据。

看看下面的示例：

```java
class Cat {
    void meow(String catName){
      System.out.println(catName + "正在喵喵叫");
    }
}

class Cat {
    void meow(String name){
      System.out.println(name + "正在喵喵叫");
    }
}
```

上述两个方法形参名叫什么，对最终方法的打印结果有影响吗？没有。因为最终到底是「谁」在「喵喵叫」，并不取决于形参名是 `catName` 还是 `name`。

真正决定「谁」在「喵喵叫」的是<font color="red">**实参**</font>：

```java
Cat cat = new Cat();
cat.meow("姜磺");  // 姜磺正在喵喵叫
cat.meow("大壮");  // 大壮正在喵喵叫
```

## 4.3 入口方法

来看一段 Python 代码：

```python
a = 3
b = 4
print(a)
def show():
  print("hello")
show()
```

这段代码很好理解。当执行这段 Python 代码时，第 1 行就是整个程序的起始点，Python 将依次执行代码。

但 Java 就不太一样了：

```java
class Cat {
    void meow(){
      System.out.println("正在喵喵叫");
    }
    
    void bark(){
        System.out.println("正在汪汪叫");
    }
}
```

上述这段代码，到底怎么执行呢？它不会像 Python 那样从第 1 行开始执行。

Java 定义了一个特殊的方法——<font color="blue">**入口方法**</font>，作为整个 Java 程序的「起始点」：

```java
public class Sample {
    // 入口方法 - 程序入口
    public static void main(String[] args) {
      System.out.println("Hello");
    }
}
```

运行上述代码，会打印出「Hello」。而第 3 行的 `main` 方法，就是入口方法。

### 入口方法的签名

入口方法的方法签名<font color="red">**必须是**</font>：

```java
// 除了形参名args可以换其他名字,其他都不能改变
// 改变了就不是入口方法了
public static void main(String[] args)
```

这里出现了 `public`、`static`、`String[]` 等还未学习的知识，可以暂时忽略。

虽然能打印出「Hello」，但仔细分析，有一些奇怪。

之前说过，方法必须要显式调用才会被执行。但上述代码没有调用 `main` 方法。

```java
main();  // ← 并未出现这样的方法调用
```

而这恰恰就是入口方法的特殊之处。

实际上入口方法的调用不是由程序员负责调用的，也根本不需要关心谁去调用的 `main` 方法。总之，一段 Java 程序在启动后，<font color="red">`main` 方法就会被自动调用</font>（不是我们调用的），这样整个程序才会有一个「入口」点，才会执行打印语句打印出 `Hello`。

### 入口方法的位置

入口方法和它所在的类没有关系。比如也可以将 `main` 方法放在名为 `Demo` 的类中：

```java
// main方法可以在Sample类、Demo类中,也可以在其他任何类中
public class Demo {
    // 入口方法 - 程序入口
    public static void main(String[] args) {
      System.out.println("Hello");
    }
}
```

一种约定俗成的做法是，入口方法通常会放置在一个名为 `Main` 的类中：

```java
// Main类通常被称为入口类
public class Main {
    // 入口方法 - 程序入口
    public static void main(String[] args) {
      System.out.println("Hello");
    }
}
```

> **提示**  
> 大多数情况下，一段独立的 Java 程序都必须有一个入口方法，否则 Java 程序是无法执行的。  
>   
> 在一些 Java Web 应用（如 Servlet 中），或者单元测试等特殊场景下，可以不需要 `main` 方法就能够启动 Java 程序。但这不属于初学者应该关心的范围。
