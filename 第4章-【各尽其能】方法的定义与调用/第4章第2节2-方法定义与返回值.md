## 2.1 方法：类的行为

类有特征和行为。特征用字段表示，行为用方法表示。

看一段代码：

```java
class Cat {
    // 字段表示类的特征
    String name;  // 猫的名字
    int age;      // 猫的年龄

    // 方法表示类的行为
    void catchMouse() {
        System.out.println("正在抓老鼠... 嗖!抓到一只大老鼠!");
    }
}
```

这段代码包含一个名为 `catchMouse` 的方法。方法在定义时需要遵循一定的语法结构。

## 2.2 方法的语法结构

方法定义包含以下几个部分：

```java
返回类型 方法名(参数列表) {
    // 方法体
    // 具体的行为逻辑
}
```

以 `catchMouse` 方法为例：

- <font color="red">**返回类型**</font>：`void`（表示不返回任何数据）
- <font color="red">**方法名**</font>：`catchMouse`（小驼峰命名，首字母小写）
- <font color="red">**参数列表**</font>：空括号 `()`（表示不需要参数）
- <font color="red">**方法体**</font>：花括号 `{}` 内的代码，用 `System.out.println` 打印文本

方法名的命名规则与字段相同，使用<font color="red">**小驼峰命名法**</font>：首字母小写，后续单词首字母大写。例如：`catchMouse`、`eatFish`、`sleepQuietly`。

## 2.3 什么是参数

参数是方法非常重要的概念。

举个数学例子，对于函数：

```text
y = 2x + 1
```

要求得 y 的值，必须输入 x 的值到函数中计算。比如 x=3 时，y=7；x=5 时，y=11。

为了求得 y 的值，必须输入 x 的值，x 就是一个「参数」。

再举一个生活中的例子：

> **场景**：餐馆点餐  
>   
> **顾客**：「我要一份宫保鸡丁！」  
>   
> **厨师**：听到点单后开始做菜  
>   
> **服务员**：将菜端给顾客

方法就像餐馆的厨房。厨房确实有做饭的功能，但如果顾客不点菜，厨房根本不知道要做什么。

顾客点的菜就是「参数」。顾客必须点菜，才能完成整个吃饭的流程。

从上面两个例子可以看出，「参数」就是为了实现某种目的必须要提供的一些数据：

- 如果没有参数值，就无法被计算
- 如果不知道顾客点了什么菜，厨房这个方法就没办法做出菜来

## 2.4 参数的类型

方法输入的参数也是数据，只要是数据，就必须指定数据的类型。

以下类型均可以用作参数的数据类型：

### 基本数据类型

最常见的是 8 种基本数据类型：

```java
void process(int number, double price, char grade, boolean flag) {
    // 参数可以是int、double、char、boolean等
}
```

### 引用类型

之前谈到的引用类型也可以作为参数的类型，比如 `String` 字符串类型：

```java
void greet(String name) {
    System.out.println("你好," + name);
}
```

### 自定义类类型

甚至一个类也可以成为参数的类型：

```java
class Cat {
    // 字段:猫咪的基本状态
    int age;
    double weight;
        
    // 方法:喂食
    // 方法参数:食物名称、以及是谁来喂这只猫
    // 这个方法的第2个参数就是一个自定义类Person(人)
    void feed(String foodName, Person person) {
        System.out.println(person.name + "正在喂" + foodName);
    }
}
```

理论上，<font color="red">**任何可以用来定义变量的类型都可以作为参数的类型**</font>。这很好理解，因为参数实质上也是一个变量，只不过它位于方法的参数列表中，是一种特殊的变量。

## 2.5 使用 return 返回数据

有时我们需要计算整数的加法，可以用下面的方法：

```java
int add(int a, int b){
  int s = a+b;
}
```

`add` 方法作为计算整数的「行为」，可以将参数 a 和参数 b 相加得到一个新的变量 s。

但问题是：这个计算结果 s 位于方法体的内部。如果需要在方法之外使用 s，上述代码就无法实现这个需求。

这有点类似于：在餐馆点了菜，厨师也做好了菜，但没有服务员将菜送到大堂。菜是做好了，但实际上却吃不到。

要解决这个问题，需要将方法的计算结果返回到方法外部。在 Java 中，可以使用 `return` 关键字来返回一个数据。

```java
int add(int a, int b){
  int s = a+b;
  return s;  // 将s返回到方法外面
}
```

当计算出「和」后，用 `return` 关键字将 s 返回到方法外面去。至于返回到外面有什么用、怎么用，暂不在目前的讨论范围。

## 2.6 方法的返回类型

对于 Java 而言，当方法有返回值的时候，就<font color="red">**必须标注返回值的类型**</font>，称为「方法的返回类型」。

由于返回的变量 s 是 int 类型，所以方法的返回类型也是 int。返回类型通常需要写在方法名前面。

```java
// 返回类型    方法名    参数列表
   int        add      (int a, int b)
```

理论上，<font color="red">**任何可以用来定义变量的类型都可以作为方法的返回类型**</font>。这一点，同方法的参数类型一样。

```java
String getName() {
    return "姜磺";
}

double calculatePrice() {
    return 99.99;
}

boolean isActive() {
    return true;
}
```

> **提示**  
> 一个 Java 方法只能返回一个数据。比如，想同时返回 s1、s2 这两个变量，这是不支持的。但可以通过其他变通的方法，比如数组、列表、对象等方式间接返回多个数据。

## 2.7 void 关键字

当一个方法不返回任何数据时，方法前面需要使用 `void`。

```java
// 方法没有返回数据
// 所以方法前需要用void关键字标记
void feed(String foodName) {
    System.out.println("正在喂"+foodName);
}
```

上述代码中，`feed` 方法没有返回任何数据，所以必须使用 `void` 关键字。

但这里有一个很多程序员忽略的问题：

```java
class Cat {
    String name;
    
    void feed(String foodName) {
        System.out.println("正在喂"+foodName);
        return;  // ← 注意这里
    }
    
    String getName(){
      return "姜磺";  // ← 这里return返回了数据
    }
}
```

在 `feed` 方法中，也有一个 `return`，可是 `return` 后面并没有返回任何数据。

这样写是没有问题的。只要方法没有返回值，就必须使用 `void` 关键字，和是不是有 `return` 没有关系。

### void 方法的错误用法

下面的代码是<font color="orange">**错误**</font>的：

```java
void getName(){
  return "姜磺";  // 错误:方法标记void但不能返回值
}
```

`getName` 方法返回了一个字符串「姜磺」，但方法标记了 `void`，这就是错误的写法。因为方法有返回值，不能使用 `void` 标记方法。

### return 单独使用的意义

`return` 后面什么都不返回有什么作用？这种写法可以<font color="red">**终止代码执行，提前结束方法**</font>：

```java
class Cat {
    String name;
    
    void feed(String foodName) {
        System.out.println("正在喂"+foodName);
        return;
        int a = 3; // ← 不会执行,因为return已经结束了方法
    }
}
```

上述代码中，`int a=3` 不会执行，因为方法在 `return` 时就已经结束执行了。

### 编码建议

如果有可能，<font color="red">**尽量让方法始终有一个返回值**</font>，哪怕返回的是最简单的 `true` 或者 `false` 这种布尔类型，也比什么都不返回要好。

这是一种良好的编码习惯，可以提高程序的测试强度，帮助减少代码的错误。

实在没有返回值时，才使用 `void` 关键字。
