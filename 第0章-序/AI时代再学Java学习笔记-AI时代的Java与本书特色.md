
课文开篇先回答你脑子里那句：

> AI 都能写代码了，我还学 Java 干嘛？

<font color="red">答案不是「不用学」，也不是「继续把语法背熟」。而是：有必要学，但学的重点变了。</font>

过去拼的是「谁更熟 Java 语法、谁敲得更快」。今天 AI 已经能替你写大量代码，<font color="orange">语法不再是最重要的门槛</font>。真正拉开差距的是：

- 怎么想问题
- 怎么把大事拆成步骤和结构
- 怎么指挥 AI、验收 AI、在它犯错时纠正它

你依然是程序的<font color="red">第一责任人</font>，AI 不是。

这一节没有要你敲代码。学完你应该能用自己的话讲清：

1. AI 时代程序员的价值在<font color="blue">决策层</font>，不在<font color="blue">执行层</font>
2. 为什么还选 Java 当「练脑」语言
3. 这本书用什么节奏教（任务驱动 + PRIMM + 反问 + 脚手架 + 一条任务链）

## 2. 核心术语词典

后面正文会反复出现这些词。先建立「词典感」，不要死记英文，先知道<font color="blue">它到底指什么</font>。

| 课文原词 | 语义化理解 | 前端类比 |
|----------|------------|----------|
| 执行层 | 把已经想清楚的方案变成代码、页面、接口 | 按设计稿把 Vue 组件写出来；或让 Cursor 按 spec 生成代码 |
| 决策层 | 该不该做、做成什么样、模块怎么切、选哪套方案 | 要不要做这个功能、用 Pinia 还是模块级 `ref`、接口谁来鉴权 |
| 第一责任人 | 程序对不对、能不能维护，责任在你不在 AI | 你 merge 了这段代码，线上炸了是你的，不是模型的 |
| 软件工程 | 用工程方法管需求、设计、质量、协作，而不只是「能跑」 | 先写技术方案 / 接口约定，再动手；PR、Code Review、测试 |
| PRIMM | Predict→Run→Investigate→Modify→Make，一套固定学法 | 先读别人组件 → 猜渲染结果 → 跑起来 → 拆 props → 改一点 → 自己写 |
| 最近发展区（ZPD） | 略高于你现在水平、有人扶一把就能做到的区间 | 教程难度：不是「你已经会的」，也不是「直接让你写整个后台」 |
| 脚手架（Scaffolding） | 先给完整示例和提示，再逐步撤掉扶手 | 一开始给完整 `App.vue`；后面只给接口形状，让你自己补页面 |
| 任务驱动 | 先有一个要解决的问题，再为了这个问题学语法 | 不是先背完 Vue API 再做项目，而是「要做聊天页，所以才学列表渲染」 |
| 任务链 | 整本书围着**同一个程序**往上加模块 | 不是每章一个玩具 demo，而是 16 章共做一个可运行的小系统 |
| Vibe Coding | 用自然语言指挥 AI 写代码 | 你在 Cursor 里下指令、改规则、验收 diff 的那种开发方式 |
| 开闭原则 | 对扩展开放、对修改关闭：加能力尽量不改旧代码 | 加新场景就加新 composable / 新路由，而不是把 `App.vue` 改成 2000 行 |
| 类 / 对象 | 类是图纸，对象是按图纸造出来的实例 | 组件定义 vs `<MyCard />` 真正挂到页面上的那一份 |

## 3. 为什么 AI 时代还要学 Java

### 3.1 先给结论，再展开

<font color="red">有必要学，但学的重点和以前不一样了。</font>

| 以前常见的学法 | AI 时代更值钱的学法 |
|----------------|---------------------|
| 把语法背熟、手速快 | 把问题想清楚、结构拆清楚 |
| 从零逐行敲完 | 指挥 AI 生成，你负责设计与验收 |
| 「能跑就行」的个人小脚本 | 能进企业项目的严谨结构 |
| 把 AI 当自动补全 | 把 AI 当助手，你当负责人 |

目前的 AI <font color="orange">还不能全自动完成一个正经项目</font>。它很听话、很能干，但下面这些它做不好（或做了你也不能盲信）：

- 帮你决定这个功能<font color="red">到底应不应该做</font>
- 帮你判断这个设计<font color="red">以后好不好维护</font>
- 帮你在多种方案里<font color="red">做权衡</font>
- 在复杂项目里理解力不够，会写出一堆<font color="orange">能跑但逻辑错、结构烂、有隐患的 BUG</font>

<font color="green">前端类比：</font>你已经在用 Cursor / Copilot。它能很快写出一个 Vue 页面，但「这个状态该放 `ref` 还是 Pinia」「密钥能不能进前端」「会话树该长什么样」——这些决定仍然是你的。AI 写得越快，你若没有判断力，屎山也堆得越快。

### 3.2 执行层 vs 决策层（这是本节最重要的一张图）

课文原话大意：AI 只解决了「执行层」，解决不了「决策层」。

```text
决策层（人必须会）                         执行层（AI 越来越强）
─────────────────────────────           ─────────────────────────────
要不要做这个功能                          把函数体写出来
模块怎么切、数据怎么流                    把样板代码补全
接口契约、错误该怎么暴露                  按你给的结构填实现
方案 A / B 怎么权衡                       把单测、提交信息写出来
AI 写完了，这段能不能合                   语法、API 调用、格式化
```

<font color="red">专业开发者和「会让 AI 出一段能跑的代码的普通人」，差别主要在决策层：更严谨的程序思维、更好的架构能力。</font>

人人都能让 AI 写个小工具；个人玩具和企业项目之间，仍然差着工程纪律、边界、可维护性。这正是计算机专业（以及你这种要进后端/全栈的前端）还要学的东西。

<font color="orange">不要把「AI 会写代码」理解成「我可以不会思考」。</font> 越依赖 AI，越要会拆问题、会验收。否则你只是那个「复制粘贴的人」。

### 3.3 你学完这本书，作者希望你变成什么样

<font color="purple">不是语法背得很熟的学生，而是：</font>

- 能看懂常见 Java 代码，<font color="red">AI 写错时你能纠正它</font>
- 养成工程师思维（先想清楚再动手，有结构、有质量判断）
- 真正具备解决问题的能力

后面章节会用朴素语言讲概念，<font color="orange">不要求死记硬背语法</font>，而是带着你做任务、做小项目，在实践里形成思维方式。

学完回头看，目标是这句话：

> <font color="red">AI 不再是让人害怕的黑盒子，而是一个真正能被你驾驭的工具。</font>

## 4. 为什么是 Java，不是 Python / TypeScript

课文承认得很干脆：<font color="blue">当前 AI 开发生态里，Python 和 TypeScript 是「王者」</font>。那为什么这本书还让你学 Java？给了两点，建议你都记住，别只记其中一条。

### 4.1 原因一：现实世界的底座大多还是 Java

看起来 AI 很热闹，但<font color="red">人类世界里大量软件基础设施，仍然是 Java 等传统语言在撑着</font>（银行、电商、政务、企业内部系统、安卓……）。

今天的局面更像：

```text
Java / 传统后端     →  做基础建设、核心业务、高并发服务
Python / TypeScript →  做 AI 部分（训练、脚本、Agent、前端 AI 应用）
```

AI 在「辅助你写代码」上已经很强，但「AI 能力本身全面长进日常生活的每个软件里」还早。所以：

- 你若要碰企业存量系统、后端岗位、Android，Java 仍然是普通话
- 你若只做纯 AI demo，可能会觉得 Python/TS 更顺；但课文的立场是：<font color="orange">基础设施这一层并没有被替换掉</font>

<font color="green">前端类比：</font>你可以只用 Vue 写新页面，但公司里仍有一堆 jQuery / 老后台 / Java 接口。AI 再强，这些系统也不会一夜之间消失。你要对接它们，就得能读懂那边的语言和结构。

### 4.2 原因二：Java 更适合「练思维」，Python / JS 太自由

课文原意：程序员或计算机系学生，<font color="red">程序的严谨性和编程思维很重要</font>；Java 是最适合训练这种思维的语言，这一点 Python 和 JavaScript 比不了。

为什么？不是因为 Java「更高级」，而是因为它<font color="blue">更受限、更严谨</font>：

- 类型必须先说清楚，乱塞类型会直接编不过
- 类、访问控制、接口、异常，把「边界」写在语法里
- 在规范受限的环境里学思想，比在完全自由的环境里学，更不容易养成坏习惯

<font color="green">前端类比（这条对你特别有用）：</font>

| 更自由 | 更严谨 | 练思维时更像谁 |
|--------|--------|----------------|
| JavaScript | TypeScript 严格模式 | Java 更接近「严格 TS + 强制面向对象」 |
| 一个 `.js` 里随便堆 | 要模块、要类型、要边界 | Java 逼你先想「这是谁的职责」 |
| Python 脚本「先跑起来」 | Java「先过编译器」 | 编译器像一个严厉的 Code Reviewer |

你已经会 JS/TS 的话，可以把 Java 想成：<font color="green">一门从第一天就打开了最严 TypeScript、并且默认用 class 组织世界的语言。</font> 别怕啰嗦，啰嗦本身就是在训练你把结构想清楚。

## 5. 学 Java 是在练什么能力

课文写得很明确：学 Java 不只是为了写几行代码，而是借这门语言训练三件事。

### 5.1 用「类」和「对象」描述现实事物

现实里有「玩家、商店、战斗、商品」。Java 会逼你问：

- 这是一种<font color="blue">东西</font>（类），还是某一次具体的<font color="blue">实例</font>（对象）？
- 它有哪些数据（字段）？会做哪些事（方法）？

<font color="green">前端类比：</font>你写过组件。`PlayerCard.vue` 是图纸（类），页面上出现的那个玩家卡片是实例（对象）。`props` 像字段，`methods` / 事件像行为。Java 把这件事做成整个语言的中心，而不只是 UI 层的习惯。

### 5.2 把零碎小功能，组合成有条理的程序

不是 20 个互不相干的 `main`。而是：这个方法属于这个类，这个类被那个菜单调用，数据从这里流到那里。

<font color="green">前端类比：</font>把「发消息、拉历史、渲染 Markdown」拆成 API / composable / 页面，而不是全写在 `App.vue`。Java 课会用「一个持续长大的程序」逼你做这种组合。

### 5.3 在规则比较严格的环境里，写出干净、稳定的代码

有访问控制、有类型、有异常必须处理。你会觉得烦，但烦的点正是企业项目里「不能随便来」的那些点。

## 6. 理解 Java，才能更好理解软件工程

### 6.1 为什么「软件工程」以前像空话，现在突然有用

课文原意可以翻译成：

- 过去很多人嘴上说软件工程重要，真下功夫的少
- 国内不少环境是「上手就做、项目生命周期不到一年、大量演示型项目」，工程方法显得<font color="orange">不实用</font>
- <font color="red">AI 时代的开发方式变成：先写文档，再交给 AI 编码</font>
- 于是你必须有严谨的工程思维和科学的管理方法——这正是软件工程给程序员的能力

<font color="green">这和你正在做的事几乎是同一句话：</font>你在 Cursor 里先把需求、规则、数据形状写清楚，AI 才写得出能维护的代码。文档/规则写得糊，生成的代码就糊。软件工程不再是「考试科目」，而是<font color="red">指挥 AI 的操作系统</font>。

```text
旧习惯：边想边敲 → 能跑就交差
AI 时代：想清楚（文档/结构/边界）→ AI 执行 → 人验收 → 再迭代
```

### 6.2 为什么说 Java 是软件工程很好的践行者

课文提到：类、开闭原则、设计模式，这些思想在 Java 里体现得很充分。

不是其他语言做不到，而是：

> <font color="red">Java 做起来更简单——它天生严谨；在规范受限的语法环境里学习编程思想，远比在自由开放的环境里学习更容易。</font>

<font color="green">前端对照：</font>

- JS 里你「可以」模块化、可以类型化、可以遵守开闭原则，但语言不强迫你
- Java 里你「不太容易」把所有逻辑塞进一个文件还假装没发生——编译器、访问控制、类型系统会一直提醒你

所以这本书选 Java，不完全是为了让你去找 Java 工作，更是：<font color="purple">用一门严谨的语言，把工程思维练进肌肉里。</font> 练会之后，你写 TS / 看 Python，也会更有结构。

## 7. 任务驱动：从能敲代码到能解决问题

<font color="purple">这本书不以语法表为目录主线，而以任务为起点。</font>

### 7.1 三个做法

**以任务为起点，而不是以语法为起点**  
每个知识点放进一个小任务或小项目里，例如「做一个简单的记账工具」「做一个抽奖程序」。不是先把 `if` / `for` / `class` 背完再找地方用。

**先有需求，再学语法**  
先描述一个贴近生活的目标，再一起想：

1. 这个问题需要哪些步骤？
2. 这些步骤能不能拆成更小的功能？
3. 哪些交给 Java 代码和 AI 来完成？

**同一个概念会在不同任务里反复出现**  
不是「这章讲完 `if` 就再也不见」。你会从「知道怎么写」变成「知道什么时候该用」。

### 7.2 和你熟悉的前端学习路径对齐

| 低效（课文反对的） | 这本书的方式 | 你以前若这样学前端 |
|--------------------|--------------|--------------------|
| 先背完整语法手册 | 先有一个要做的东西 | 先背完 Vue 所有 API 再写页面 |
| 知识点孤立成节 | 知识点为任务服务 | 每章一个互不相关的 demo |
| 会写但不会用 | 同一概念多任务复用 | 学过 `watch` 但不知道何时不该用 |

<font color="orange">如果你习惯「先把这一章语法抄进笔记再往下」，建议改成：先看本章任务要你交付什么，再倒回去学语法。</font> 这和后面的 PRIMM 是配套的：先看见程序在干什么，再学那几行字是什么意思。

## 8. PRIMM 节奏：看懂–预测–运行–拆解–改写–创造

这是本书的<font color="purple">固定学习节拍</font>。后面每章正文里会看到 `[P]` `[R]` `[I]` `[M]`，指的就是这一套。

来源：英国计算机教育研究者、剑桥大学树莓派计算教育研究中心主任 **Sue Sentance** 提出的 <font color="blue">PRIMM</font> 编程学习模型。

| 步骤 | 英文 | 课文要求你做什么 | 训练的能力 |
|------|------|------------------|------------|
| 预测 | **P**redict | 先给一小段**完整可运行**代码，问你：会输出什么？会发生什么？ | 对程序行为的预判，而不是一上来就写 |
| 运行 | **R**un | 带着猜测去跑，看结果是否和你想的一样 | 用事实校正直觉 |
| 拆解 | **I**nvestigate | 为什么是这个结果？哪一行起了关键作用？改一部分会怎样？ | 读代码、定位、建立因果 |
| 修改 | **M**odify | 在已有代码上做**小改动**（改条件、换输入、加分支/循环） | 安全地试、观察、验证 |
| 创造 | **M**ake | **最后才**从零写一段新代码 | 这时你已经看过、跑过、分析过、改过，上手更有信心 |

课文用了一个很好的比喻：

> <font color="purple">像拆乐高：先看成品，再看结构，再自己搭一遍。</font>

<font color="orange">千万不要一上来就「从零默写」。那是旧时代练手速的方法，也是最容易被陌生语法吓退的方法。</font>

### 8.1 前端版 PRIMM（你可以立刻用来学 Java）

假设下一章给你一段 `Player` 的 Java 代码：

```text
[P] 先不写。盯着代码问：main 跑完会在控制台印什么？
[R] 真的编译运行（或让 AI 跑给你看），对答案
[I] 问三句：哪一行创建了对象？哪一行改了数据？去掉这行会怎样？
[M] 只改一处：比如把生命值改成 80，或加一句打印
[M] Make：合上示例，按任务要求自己写一个最小版本
```

<font color="green">这其实就是你会的前端学习法：</font>先 clone 一个能跑的页面 → 猜点击后会发生什么 → 打开 DevTools 验证 → 读 props/emit → 改一个文案或加一个按钮 → 最后自己写同类页面。Java 课把这套节奏写死了，每章都走一遍。

### 8.2 两个 M 容易混

Modify（改）和 Make（造）英文都可能标成 `[M]`。阅读时看上下文：

- 在已有代码上动一刀 → <font color="blue">Modify</font>
- 从零写 → <font color="blue">Make</font>

不要跳步：没 Predict/Run/Investigate 就直接 Make，等于又回到「被语法吓到」的旧路。

## 9. 反问式提问：训练你会问

<font color="purple">每个章节都用「反问式提问」讲知识点：不先甩定义，先抛问题。</font>

课文举的例子：

- Python 这么流行，我们为什么还要学 Java？
- 字段用名词、方法用动词，这是强制的吗？
- 一个类可以没有字段或方法吗？

这些问题看起来简单，恰恰是你写代码时会卡的地方。主动想一遍，再看讲解，印象会深得多。

### 9.1 课文说的三个「为什么要反问」

**符合认知规律**  
大脑不是容器，是自己建构知识的系统。面对问题，你会调用已有知识尝试回答——这比被动听讲有效。心理学里常说：<font color="red">主动检索比被动重复阅读，学习效果大约好 3～5 倍</font>（把这句话当成「要先猜、再看答案」，不要当成精确科学公式去背）。

**培养批判性思维**  
别停在「老师说什么就是什么」。对每个知识点追问：

- 为什么 Java 要强制用分号？
- 为什么类名必须和文件名一致？
- 这样设计的好处是什么？不这样会怎样？

**适应 AI 时代的核心能力**  
通用知识问答上，模型往往比人强。<font color="red">会提问题，已经成为程序员最核心的能力之一。</font> 用 ChatGPT、DeepSeek、Cursor 时：<font color="red">提问质量直接决定回答质量。</font>

<font color="green">前端类比：</font>你对 Cursor 说「帮我做一个登录页」，和说「用 Vue3 + 现有 `useAuth`，手机号+验证码，错误文案走已有 toast，不要引入新 UI 库」——产出完全不是一个量级。这本书用反问训练的，就是后一种提问肌肉。

### 9.2 你自己可以准备的「反问清单」

后面每学一个 Java 概念，至少问这四句：

1. 它在解决什么问题？（没有它会怎样？）
2. 和我熟悉的 JS/TS/Vue 里哪件事像？
3. AI 最容易把哪一点写错？
4. 在本章任务里，它出现在哪一步？

## 10. 最近发展区与脚手架

难度设计遵循：<font color="blue">最近发展区（Zone of Proximal Development, ZPD）</font> + <font color="blue">脚手架（Scaffolding）</font>。

### 10.1 两个词不要混

| 词 | 一句话 | 不是什么 |
|----|--------|----------|
| 最近发展区 | 比你现在稍难一档、有指导就能做到的区间 | 不是「超难装杯」，也不是「重复你已会的」 |
| 脚手架 | 学习时提供的扶手：完整代码、详细步骤、提示 | 不是永远不撤的复制模板；目标是撤掉之后你还能走 |

### 10.2 三个阶段（全书都会按这个撤扶手）

```text
阶段1 给足扶手
  完整代码 + 详细提示 + 清晰步骤
  你只需要盯少数几个新点，不会被细节淹没

阶段2 逐步减少提示
  示例变少、提示变短
  留给你自己想和试的空间变大

阶段3 独立完成小项目
  几乎没有提示，从需求到代码自己走完
  这时思维能力才算真正被训练起来
```

<font color="orange">如果某章你完全不看示例就能做：偏简单了，可以主动加约束（比如禁止 AI 直接生成全文，先自己 Predict）。</font>  
<font color="orange">如果某章完全看不懂示例：不是你笨，是跳步了——回到 PRIMM 的 P/R/I，不要直接 Make。</font>

<font color="green">前端类比：</font>官方教程先给你整个 Vite 项目；你熟悉之后，新需求只会给你接口文档。脚手架撤掉的过程，就是从「会跟着做」到「会自己做」。

## 11. 任务贯穿：一本书搭出一个程序

<font color="purple">本书用一条任务线把知识连起来，不靠角色扮演、冒险剧情来包装。</font>

注意课文原句是「不设置角色冒险」——意思是<font color="orange">教学上不用小说情节带你玩</font>，但做出来的程序本身仍是一个可交互的小世界（玩家、区域、商店、战斗）。别理解成「这书不做游戏」，而是「每章开门见山布置任务，不先绕故事」。

### 11.1 怎么贯穿

- **每章直接布置任务**：开头就给任务目标、已有基础、需要实现、完成标准
- **任务互相衔接**：前面的类和方法，会成为后面的已有基础  
  例如：先定义 `Player` → 再给它加方法、战斗逻辑、菜单、数据管理、封装、异常处理 → 最后重构
- **整本书结束时，你得到一个可运行的 Java 程序**：可以从主菜单查看状态、进入区域、进入商店、处理战斗，并验证数据安全和数据管理流程

```text
第1章 先能描述「世界上有什么」（类 / 对象思想）
  → 定义 Player 等核心概念
  → 为它添加方法（行为）
  → 战斗 / 菜单 / 商店（流程与结构）
  → 数据怎么存、怎么保护（封装、异常）
  → 重构收口
```

<font color="green">前端类比：</font>不是第 1 章做 Todo、第 2 章做天气、第 3 章做计算器，而是<font color="red">16 章共做一个会越来越大的 Vue 应用</font>——先有用户对象，再有页面，再有路由，再有持久化。前面写的文件后面还要用，所以从第 1 章起就要有结构意识。

### 11.2 和第0章另外两节的分工（避免学重）

| 节 | 标题 | 你在这节已经得到的 | 留给后面的 |
|----|------|--------------------|------------|
| 第1节（本课） | AI时代的Java与本书特色 | 为什么学、学什么、怎么学 | 不讲具体任务步骤 |
| 第2节 | 写给学生 | — | 学习建议、心态、使用方法 |
| 第3节 | 全书任务链 | 本课只剧透「会做成一个可交互程序」 | 16 章任务如何一环扣一环的完整地图 |

## 12. 计算机英语：为 Vibe Coding 铺路

### 12.1 先打破一个迷信

很多人觉得「数学决定编程水平」。课文的判断是：

- 绝大多数程序员做的是<font color="blue">应用层开发</font>
- 需要很深数学的，主要是算法研究，只占很小一部分
- 从长期教学看，真正影响水平的核心因素是 <font color="red">逻辑思维</font> 和 <font color="red">英语能力</font>
- 在 AI 已经能支持自然语言编程（<font color="blue">Vibe Coding</font>）的今天，<font color="red">语言能力更重要了</font>

对你这种前端：数学焦虑可以先放下；<font color="orange">更该担心的是：术语不熟、官方文档读不进去、给 AI 的指令含混、变量还在用拼音。</font>

### 12.2 为什么英语对程序员重要（三条都要）

**1. 技术文档阅读**  
主流官方文档以英文为主。AI 翻译能换语言，但<font color="orange">很难完整保住技术逻辑和作者原意</font>。你会越来越需要「直接读英文小节」，而不是整页丢给翻译。

**2. 编程语言本身是英语思维**  
现代主流语言是按英语习惯长出来的。`getUserById`、`isEmpty`、`try/catch` 用英语想，会更顺。用中文语序硬套，命名和结构都容易别扭。

**3. 职业规范**  
除了极少数场景，变量名、函数名要用英文。这是协作和可维护性的底线，不是崇洋。

<font color="green">前端类比：</font>你已经见过 `ref`、`computed`、`watchEffect`。Java 里会有 `class`、`interface`、`extends`、`throws`。同一套「用英文单词当积木」的习惯。Vibe Coding 时，你用中文说需求可以，但<font color="red">落到代码标识符，仍然是英语积木</font>——积木不认识，就指挥不准。

### 12.3 这本书怎么帮你练英语

- 每章末尾有「本章英语词汇」：大约 10～15 个核心术语，带音标、词性、记忆技巧、在编程里怎么用
- 练习里会有：词汇填空、英语阅读、变量/函数命名训练

<font color="purple">建议：词汇表不要只收藏。每章至少用英语把 3 个标识符按规范命名一遍（类用大驼峰，方法用动词）。</font>

## 13. 阅读符号速查（后面每章都会用）

课文为了简洁和跨平台，尽量用 ASCII 能打出来的标记。**从现在起把这张表当图例**，后面不再每次解释。

### 13.1 PRIMM 流程标记

| 标记 | 含义 | 你该做什么 |
|------|------|------------|
| `[P]` | Predict 预测 | 先猜输出/行为，先别写 |
| `[R]` | Run 运行 | 跑代码，对答案 |
| `[I]` | Investigate 拆解 | 追问为什么、哪一行关键 |
| `[M]` | Modify 修改 **或** Make 创造 | 看上下文：改已有 vs 从零写 |

### 13.2 内容提示标记

| 标记 | 含义 | 阅读时的态度 |
|------|------|----------------|
| `[*]` | 要点 / 重点 | 等同本文红色：合上书要能复述 |
| `[?]` | 思考题 | 先自己答，再看后文 |
| `[!]` | 提示 / 注意事项 | 等同本文橙色：容易踩坑 |
| `[×]` | 错误 / 不推荐 | 反例，不要学它的写法 |
| `[√]` | 正确 / 推荐 | 正例，作为默认习惯 |

### 13.3 结构符号与行号

课文还用 `├─` `└─` `│` 画层级（知识图谱、目录树）。严格说它们不是 ASCII，而是盒线字符；不影响阅读，把它当成「树形列表」即可。

讨论代码时用 `#num` 指行号：`#1` 是第 1 行，`#3` 是第 3 行。  
<font color="orange">这和 Markdown 标题 `#` 不是一回事。</font> 在「讲某一行代码」的语境里，`#3` = 第 3 行；在笔记标题里，`#` 才是标题。

## 15. 前端工程师特别提醒

你带着 Vue / 小程序 / TS 背景来学，容易有三个误判。课文没点你的名，但和本节强相关：

### 15.1 「我已经会编程了，Java 只是换套语法」

会前端说明你会：状态、组件、异步、工程化的一部分。  
Java 要补的是：<font color="red">以类为中心的建模、更严的类型与边界、没有浏览器这个运行时之后的程序怎么组织。</font>  
把 Java 当成「TS 换皮」会在第 1～2 章就卡住——类不是组件，`main` 也不是 `onLoad`。

### 15.2 「日常写 TS 就够了，Java 是不是过时」

课文的立场更冷静：

- AI 应用层：Python / TS 确实更热闹
- 基础设施与大量企业系统：Java 仍在
- 作为练思维的语言：Java 更合适

<font color="red">对你的实用目标可以定为：读懂 Java、能改、能指挥 AI 写 Java、能和后端用同一套面向对象语言说话。</font> 不必一上来就要求自己成为 Java 性能专家。

### 15.3 「有 Cursor，PRIMM 是不是多余」

恰恰相反。Vibe Coding 最容易变成：不读代码、不预测、不运行验证、直接让模型再生成一轮。  
<font color="purple">PRIMM 是给「人机协作」准备的刹车：先猜、再跑、再拆，最后才让 AI 大改。</font> 你在 AI 应用课里已经吃过「生成能跑但不对」的亏；Java 课把验收流程写进学习方法里了。

## 19. 自测题

建议先不翻上面正文，写完再对答案提示。

**1. 决策层 / 执行层**  
用一个你真实做过的前端需求（比如聊天页、登录页），各举一件「必须人决定」的事，和一件「可以交给 AI 写」的事。  
提示：前者如「会话数据按 userId 还是按 convertId 存」；后者如「把列表渲染的模板写出来」。

**2. 为什么还学 Java**  
课文给了两点。请用自己的话各写一句，不要出现「因为老师说要学」。  
提示：底座 + 练思维（严谨、受限）。

**3. PRIMM 排序**  
把 Make、Investigate、Predict、Modify、Run 排成正确顺序，并写一句：为什么 Make 必须放最后。  
提示：P-R-I-M-M；最后才从零写，是因为前面已经建立直觉和因果。

**4. 反问与 Vibe Coding**  
把「帮我写个 Java 玩家类」改写成一条更高质量的指令（包含：已有上下文、约束、完成标准）。  
提示：质量来自问题是否具体，这正是本节说的核心能力。

**5. 脚手架**  
如果第 5 章几乎不给完整代码了，按「最近发展区」你该怎么调整学习动作？  
提示：不是硬刚从零写，也不是整段丢给 AI；回到示例较少时的 Predict/Investigate，必要时回看前章已有类。

**6. 任务链**  
为什么「每章一个独立小 demo」不如「全书一个程序」更适合这本书的目标？  
提示：结构、复用、重构、工程思维，都要在「旧代码还活着」时才练得到。

**7. 符号**  
文中 `[!]`、`[×]`、`#3` 各是什么意思？`#3` 和 Markdown 标题有何不同？  
提示：注意 / 反例 / 第 3 行代码。
