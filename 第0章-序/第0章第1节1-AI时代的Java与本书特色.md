## 1.1 为什么在AI时代还要学Java

现在是AI的时代，很多同学会有疑问：AI已经能帮我写代码了，我还有必要学Java吗？这个问题很正常。本书想先告诉你一个简单的答案：<font color="red">**有必要，但学的重点和以前不一样了。**</font>

过去学编程，大家经常拼的是「谁能更熟练地用 Java 语法来表达意图」。但是在 AI 越来越强的今天，AI 已经可以直接替你写代码，<font color="orange">语法已经不再是最重要的门槛</font>。真正拉开差距的，是你<font color="red">**怎么想问题、怎么拆问题、怎么把一件事情安排成清晰的步骤和结构**</font>，然后才是交给 AI 去做。目前的 AI 还不能全自动地帮你完成项目，依然需要你来「指挥」它。

你可以把 AI 想象成一个很听话、很能干的「代码助手」。你可以不用像以前一样哼哧哼哧地敲代码，但它做不到的事情有很多，比如：

- 帮你决定这个功能到底应不应该做；
- 帮你判断这个设计以后好不好维护；
- 帮你在多种方案里做权衡和选择；
- 目前的 AI 在复杂项目里，理解能力不够，会出现很多 BUG。

也就是说，你依然是你程序的<font color="red">**「第一责任人」**</font>，而不是 AI。

所以，这个时代，我们需要思考的是，计算机专业的学生和普通人的区别在什么地方。我认为，最重要的差别在于，专业的计算机学生应该拥有更严谨的程序思维和更优秀的架构能力。虽然 AI 时代人人都能写程序，但个人程序和严谨的企业项目差别还是极大的。这依然需要计算机专业的学生学习。

换句话说，现在的 AI 只解决了「<font color="blue">执行层</font>」的问题，但它解决不了「<font color="blue">决策层</font>」的问题。程序员的<font color="red">**逻辑思维能力和基本架构能力**</font>，反而比任何一个时代都要重要。

在当前时代，Python 和 TypeScript 毫无疑问是 AI 开发的「王者」，那为什么还需要学习 Java？原因我认为有两点：

1. 看起来 AI 现在很热闹，但实际上目前大部分人类世界的软件基础设施依然是由 Java 等传统语言来构建的。AI 现在在辅助编码上很强，但 AI 功能本身没有融入到人类的日常生活中。

   所以，目前主流是 Java 用来做基础建设，AI 部分交给 Python 和 TypeScript 来做。

2. 对于程序员或者计算机系的学生，程序的严谨性以及编程的思维很重要，而 Java 是最适合训练编程思维的语言，这点 Python 和 JavaScript 是比不了的。

当然，学习 Java，不只是为了写几行代码，而是借助这门语言来训练你的：

- 如何把现实中的事物，用「类」和「对象」的方式描述出来；
- 如何把很多零碎的小功能，组合成一个有条理的程序；
- 如何在规则比较严格的环境里，写出干净、稳定的代码。

本书的目标，不是把你训练成一个「语法背得很熟」的学生，而是希望你在学完之后：

- 能看懂常见的 Java 代码，当 AI 犯错时，你可以「纠正」它；
- 养成工程师思维，这点对 AI 时代的程序员尤其重要；
- 培养解决问题的能力。

在接下来的章节里，我们会尽量用朴素、简单的语言来讲解每一个概念，不要求你死记硬背语法，而是带着你一步步做任务、做小项目，在实践中慢慢形成自己的思维方式。希望当你学完这本书回头看时，会发现：<font color="red">**AI 不再是一个让人害怕的「黑盒子」，而是一个真正能被你驾驭的工具。**</font>

## 1.2 理解 Java 才能更好地理解软件工程

我在其他书籍或者公众号里反复谈到，AI 时代最重要的是软件工程。这个在以前被很多草莽程序员忽略的学科，现在摇身一变变得实用、有用。

我们以前都说软件工程很重要，但真的下功夫学习、理解软件工程的人很少，这一点在国内程序员身上尤其突出。以前我们不想学软件工程或者学不会软件工程，主要原因是因为它在国内「上手就做」、「一个项目生命周期就 1 年不到」、「大部分是演示性质项目」的大环境下，显得毫无实用价值。

但 AI 时代不一样，<font color="red">AI 时代的开发方式是：先写文档，再交给 AI 编码。</font>这就需要我们有严谨的工程思维和科学的管理方案，这正是软件工程给予程序员的能力。

而 Java 是软件工程最好的践行者，无论是类、开闭原则、设计模式，这些思想在 Java 里体现得淋漓尽致。

不是其他语言做不到，而是 Java 做起来更简单：它天生就是一种严谨的语言，在规范受限的语法环境里学习编程思想，远比在自由开放的环境里学习更容易。

## 1.3 任务驱动：从「能敲代码」到「能解决问题」

- **以任务为起点，而不是以语法为起点**  
  每个知识点都不是孤立讲解，而是放在一个小任务或小项目中，比如「做一个简单的记账工具」「做一个抽奖程序」等。

- **先有需求，再学语法**  
  我们会先描述一个简单、贴近生活的目标，然后一起思考：
  - 这个问题需要哪些步骤？
  - 这些步骤能不能拆成一个个更小的功能？
  - 哪些地方可以交给 Java 代码和 AI 来完成？

- **在解决问题中反复用到同一个概念**  
  同一个知识点不会只出现一次，而是会在不同任务里多次用到，让你从「知道怎么写」逐渐变成「知道什么时候该用」。

## 1.4 PRIMM 节奏：看懂–预测–运行–拆解–改写–创造

本书借鉴了英国计算机教育研究者、剑桥大学树莓派计算教育研究中心主任 Sue Sentance 提出的 <font color="blue">**PRIMM 编程学习模型**</font>，把每个知识点的小节尽量设计成固定的学习节奏：

- <font color="purple">**Predict（预测）**</font>：先给你一小段完整可运行的代码，不要求你自己从零写起，而是先问你：「你觉得这段代码会输出什么？会发生什么？」——训练你对程序行为的**预判能力**。
- <font color="purple">**Run（运行）**</font>：带着自己的猜测，运行代码，看一看实际结果是不是和你想的一样。
- <font color="purple">**Investigate（拆解）**</font>：一起分析关键语句：
  - 为什么结果是这样？
  - 哪一行代码起了关键作用？
  - 如果改动一部分，会对结果产生什么影响？
- <font color="purple">**Modify（修改）**</font>：在已有代码的基础上做小改动，比如：改一个条件、换一种输入、多加一个分支或循环。通过这种「小步修改」，你会更安全地尝试、观察和验证自己的想法。
- <font color="purple">**Make（创造）**</font>：最后才是「从零写一段新的代码」。这时你已经看过、跑过、分析过、改过类似的程序，上手会轻松很多，也更有信心。

通过这样一套流程，你不会一上来就被一大堆陌生语法吓到，而是像拆乐高一样，先看成品，再看结构，再自己搭一遍。

## 1.5 反问式提问：训练提问思维

本书的每个章节都采用**反问式提问**的方式来讲解知识点。什么是反问式提问？简单来说，就是在讲解概念时，不直接给出定义和结论，而是先抛出一系列问题：

- **Python 这么流行，我们为什么还要学 Java？**
- **字段用名词、方法用动词，这是强制的吗？**
- **一个类可以没有字段或方法吗？**

这些问题看似简单，但恰恰是学习者在实际编程中会产生的困惑。通过主动思考这些问题，你会对知识点有更深刻的理解。

**为什么反问式提问是一个很好的做法？**

**符合人类认知规律**：人的大脑不是被动接收信息的容器，而是主动构建知识的系统。当你面对一个问题时，大脑会自动调用已有的知识尝试回答，这个过程比单纯听讲解要有效得多。心理学研究表明，主动检索记忆比被动重复阅读的学习效果要好 3 到 5 倍。

**培养批判性思维**：很多学生习惯了「老师说什么就是什么」的学习模式，缺乏质疑和探究的能力。反问式提问鼓励你对每个知识点都问一句「为什么」：

- 为什么 Java 要强制使用分号？
- 为什么类名必须与文件名一致？
- 这样设计的好处是什么？不这样设计会怎样？

**适应 AI 时代的核心能力**：在 AI 回答某些通用知识的能力远比人类要强很多很多，要想和 AI 很好地交流，<font color="red">**会提问题**</font>已经成为程序员最核心的能力之一。使用 ChatGPT、DeepSeek 等大模型时，你会发现：<font color="red">提问质量直接决定了 AI 的回答质量。</font>

## 1.6 最近发展区与「脚手架」：慢慢撤掉扶手

在难度设计上，本书会遵循「<font color="blue">**最近发展区 + 脚手架**</font>」的理念：

- **一开始给足扶手**：先有完整代码、详细提示、清晰步骤，让你只专注在少数几个新的点上，不会被细节淹没。
- **逐步减少提示**：随着章节推进，示例会变少，提示会变短，留给你自己思考和尝试的空间会越来越大。
- **最后能够独立完成小项目**：当你可以在几乎没有提示的情况下，从需求到代码自己走完一遍时，你的思维能力也就真正被训练起来了。

## 1.7 最终目标：用 Java 训练你的「工程师大脑」

总结来说，本书想帮你实现的是：

- **不是** 把所有 Java 语法都背得滚瓜烂熟；
- **而是** 借助 Java 这门语言，训练你：
  - 先把问题想清楚，再动手写代码；
  - 能把复杂问题拆成有条理的结构；
  - 在 AI 的帮助下，依然保持对程序质量和架构的判断力。

当你学完本书再回头看时，希望你会发现：<font color="red">**你不仅能看懂 Java 代码，更能利用 AI 成为一个「会思考、懂结构」的程序员，而不是只能复制粘贴的人。**</font>

## 1.8 任务贯穿：一本书搭出一个程序

本书用一条任务线把知识连起来，不设置角色冒险。每章都有明确任务，任务会复用前面章节完成的类、方法和数据，逐步往同一个程序里添加模块。

- **每章直接布置任务**：章节开头先给出任务目标、已有基础、需要实现和完成标准，不先用场景和对话包装。
- **任务之间互相衔接**：前面的类和方法会成为后面的已有基础。比如先定义 `Player`，再为它添加方法、战斗逻辑、菜单、数据管理、封装、异常处理和最终重构。
- **完成整本书后得到一个可交互程序**：所有模块汇成一个可以运行的 Java 程序，读者可以从主菜单查看状态、进入区域、进入商店、处理战斗，并验证数据安全和数据管理流程。

## 1.9 计算机英语词汇与阅读：为未来铺路

很多人谈到计算机编程，总会下意识认为数学是决定编程水平高低的绝对因素。但实际上，绝大多数程序员从事的是应用层面的开发工作。需要深厚数学功底的主要是算法研究领域，而这只占编程工作的极小一部分。

从长期教学实践来看，真正影响编程水平的核心因素是<font color="red">**逻辑思维**</font>和<font color="red">**英语能力**</font>。尤其是在现在 AI 已经可以支持人类做自然语言编程（<font color="blue">Vibe-Coding</font>）的现状下，语言就更为重要了。

**为什么英语对程序员如此重要？**

1. **技术文档阅读**：主流技术的官方文档以英文为主。虽然 AI 翻译工具能提供语言转换，但它无法完全保留技术逻辑和原作者的表达意图。

2. **编程语言的英语思维体系**：现代主流编程语言本质上是以英语为思维体系构建的。当你用英语思考时，代码的逻辑和表达会更加自然流畅。

3. **职业规范要求**：除了极少数特定场景，绝大多数变量名、函数名都需要使用英文命名。这是团队协作和代码可维护性的基本要求。

因此，本书在每个章节特别设计了**计算机英语学习模块**，帮你在学 Java 的同时，同步提升专业英语能力。

- **每章精选核心词汇**：每章末尾都有「本章英语词汇」部分，精选 10–15 个核心术语，提供标准音标和词性、记忆技巧、编程场景中的实际用法。

- **英语练习题**：在章节练习中，专门设计了英语相关题目：词汇填空、英语阅读理解、变量函数命名训练。

## 1.10 ASCII 符号标记说明

为了保持本书的简洁性和跨平台兼容性，本书统一使用 ASCII 符号。在阅读过程中，你会看到以下符号标记：

**PRIMM 流程标记**：

- `[P]` - Predict（预测）步骤
- `[R]` - Run（运行）步骤
- `[I]` - Investigate（拆解）步骤
- `[M]` - Modify / Make（修改 / 创造）步骤

**内容提示标记**：

- `[*]` - 要点 / 重点标记
- `[?]` - 思考题 / 问题
- `[!]` - 提示 / 注意事项
- `[×]` - 错误 / 不正确的做法
- `[√]` - 正确 / 推荐的做法

**结构展示符号**：`├─` `└─` `│` 用于展示知识图谱、代码结构等层级关系。

**代码行数引用**：在讨论代码时，本书使用 `#num` 来表示代码行数，比如 `#1` 表示代码第 1 行，`#3` 表示代码第 3 行。
