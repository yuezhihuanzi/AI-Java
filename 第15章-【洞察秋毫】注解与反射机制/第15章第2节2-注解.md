> **阅读指南**  
> 注解是贴在代码上的元数据——它不改变程序的逻辑，却能被编译器、框架和工具读取。这一节先看注解是什么、Java内置了哪些常用注解（@Override、@Deprecated等），再学自己定义注解：用@interface声明，用元注解@Target、@Retention等规定它能用在哪里、保留多久。理解了这两步，后面看Spring这类框架时就不会觉得注解是魔法。

## 2.1 什么是注解

<font color="red">**注解**</font>（Annotation）是一种形式化的<font color="red">**元数据**</font>（Metadata）。它不是程序本身的一部分，而是为代码提供关于程序本身的数据信息。

你可以把它想象成代码的"标签"或"装饰"。这些标签本身对代码的逻辑没有直接影响（除非有特定的工具处理它），但它们可以被编译器、IDE、测试框架、运行时环境等读取并用于各种目的。

```
    商品 ────────→ 条形码 ────────→ 扫描获取信息
     │                              │
     类/方法 ──────→ @注解 ──────→ 工具读取信息
```

注解本身很"懒"，它什么都不做。它的力量来自于解析和处理它的代码。注解+处理器=强大功能。没有处理器的注解就像没有扫描仪的条形码，毫无用处。

## 2.2 注解的使用场景

注解的主要目的是简化开发和减少配置，实现"约定优于配置"。常见的应用场景包括：

<font color="red">**编译检查**</font>：告诉编译器一些信息，以便进行额外的检查（如`@Override`、`@Deprecated`）。

<font color="red">**编译时和构建时生成代码**</font>：通过注解处理器（Annotation Processing Tool, APT）在编译时生成代码、配置文件等（如Lombok、Dagger2）。

<font color="red">**运行时处理**</font>：通过反射在程序运行时获取注解信息，从而执行相应的逻辑（如Spring MVC、JUnit、Jackson）。

<font color="red">**生成文档**</font>：通过javadoc工具，根据代码中的注解自动生成API文档。

这些用途无不体现注解的"编外特性"：它本身就不是Java程序的一部分。

## 2.3 Java内置注解

注解在使用时均以`@`符号开头。Java提供了一些内置的注解，主要位于`java.lang`包中。

### @Override

作用：表明一个方法声明是重写父类中的方法。

```java
public class Child extends Parent {
    @Override // 如果父类没有 toString() 方法，编译器会在这里报错
    public String toString() {
        return "Child";
    }
}
```

这个注解可以不加，但好处是让编译器帮你检查。如果拼写错误（如`toString`写成了`tostring`）或者方法签名对不上，编译器会提示你有问题。

### @Deprecated

作用：标记某个程序元素（类、方法、字段等）已过时、不推荐使用。

```java
public class OldClass {
    /**
     * @deprecated 这个方法已经过时，请使用newMethod()代替
     */
    @Deprecated
    public void oldMethod() {
        // ... old logic
    }
    
    public void newMethod() {
        // ... new logic
    }
}
```

有些方法随之版本的演进需要删除，但为了考虑兼容性又不能立即删掉（需要给程序员一定的缓冲期）。使用`@Deprecated`标记过时元素时，编译器会产生警告，提示程序员这个元素已经过时了。

### @SuppressWarnings

作用：告诉编译器忽略指定的警告信息。

```java
@SuppressWarnings("unchecked")
public void someMethod() {
    // 这里会产生unchecked警告，但被抑制了
    List list = new ArrayList();
}
```

## 2.4 自定义注解

自定义注解使用`@interface`关键字来声明，其语法与定义接口类似。注解其实是一种特殊的接口。

```java
// 使用 @interface 关键字定义
public @interface MyFirstAnnotation {
    // 注解的"元素"，看起来有点像方法，实则是可配置的参数
    String value();
    int count() default 1; // 可以使用 default 关键字提供默认值
    boolean enabled() default true;
}
```

注解下的元素有点奇怪——定义像类的方法，但根本不是方法。注解下的元素是一种可配置的参数，就像类的成员变量，需要被赋值。

使用时指定元素值：

```java
@MyFirstAnnotation(value="Lily", count=3, enabled = false)
public class MyClass {
}
```

## 2.5 元注解

注解可以用于各种Java元素上。那么可以将注解用于注解上吗？可以，这称为"<font color="red">**元注解**</font>"——用在注解上的注解，用于定义注解的基本特征。

### @Target

`@Target`用于指定自定义注解可以应用的Java元素类型。它接受一个`ElementType`枚举数组作为参数。

`ElementType`枚举值如下：

| 枚举值 | 适用元素 |
|--------|----------|
| TYPE | 类、接口、枚举 |
| FIELD | 字段（包括枚举常量） |
| METHOD | 方法 |
| PARAMETER | 形式参数 |
| CONSTRUCTOR | 构造器 |
| LOCAL_VARIABLE | 局部变量 |
| ANNOTATION_TYPE | 注解类型 |
| PACKAGE | 包 |
| TYPE_PARAMETER | 类型参数（Java 8+） |
| TYPE_USE | 类型使用（Java 8+） |
| MODULE | 模块（Java 9+） |

```java
// 只能应用于方法
@Target({ElementType.METHOD})
public @interface MethodLevelAnnotation {
}

// 可以同时用在类和方法上
@Target({ElementType.TYPE, ElementType.METHOD})
@Retention(RetentionPolicy.RUNTIME)
public @interface SimpleAnnotation {
    String value();
}
```

如果不使用`@Target`元注解，该注解可以用于除`TYPE_PARAMETER`和`TYPE_USE`之外的任何元素。但在实际开发中，明确指定`@Target`是一个很好的实践。

### @Retention

`@Retention`指定了注解的保留策略，即注解的生命周期。它决定了注解在何时可用。

`RetentionPolicy`枚举定义了三种保留策略：

```java
public enum RetentionPolicy {
    SOURCE,  // 仅在源代码中保留，编译器使用后丢弃
    CLASS,   // 保留在class文件中，但JVM加载时不可见（默认策略）
    RUNTIME  // 保留在class文件中，运行时可通过反射访问
}
```

```java
// 源码级别保留 - 用于编译期检查
@Retention(RetentionPolicy.SOURCE)
public @interface SourceRetentionAnnotation {
}

// 运行时保留 - 可通过反射访问
@Retention(RetentionPolicy.RUNTIME)
public @interface RuntimeRetentionAnnotation {
}
```

保留策略选择指南：
- <font color="red">**SOURCE**</font>：仅编译期起作用，如`@Override`、`@SuppressWarnings`
- <font color="red">**CLASS**</font>：字节码分析时起作用，但不需运行时访问
- <font color="red">**RUNTIME**</font>：运行时通过反射读取，如Spring、JUnit等框架中的注解

### @Documented

`@Documented`指示被注解的元素应该被javadoc或类似工具文档化。默认情况下，注解信息不会包含在生成的JavaDoc中。

```java
// 未使用@Documented - 不会出现在JavaDoc中
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface UndocumentedAnnotation {
    String value();
}

// 使用@Documented - 会出现在JavaDoc中
@Documented
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface DocumentedAnnotation {
    String value();
}
```

### @Inherited

`@Inherited`表示注解类型可以被自动继承。如果一个类使用了被`@Inherited`修饰的注解，则其子类将自动具有该注解。

```java
// 定义可继承的注解
@Inherited
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
public @interface InheritableAnnotation {
    String value() default "";
}

// 父类使用了@InheritableAnnotation
@InheritableAnnotation("父类注解")
public class ParentClass {
}

// 子类自动继承了这个注解
public class ChildClass extends ParentClass {
}
```

注意事项：
- 只对类级别的注解有效（使用`extends`关键字继承的子类）
- 对接口实现无效（使用`implements`不会继承注解）

### @Repeatable

在Java 8之前，同一个注解不能在同一个地方重复使用多次。`@Repeatable`元注解允许同一个注解在同一个声明上多次使用。

工作流程分两步：

<font color="red">**步骤一：定义容器注解**</font>

```java
@Retention(RetentionPolicy.RUNTIME)
public @interface Schedules {
    Schedule[] value(); // 必须返回可重复注解的数组
}
```

<font color="red">**步骤二：标记为可重复**</font>

```java
@Repeatable(Schedules.class)
@Retention(RetentionPolicy.RUNTIME)
public @interface Schedule {
    String dayOfWeek() default "Mon";
    int hour() default 0;
}
```

<font color="red">**步骤三：使用**</font>

```java
public class TaskScheduler {
    @Schedule(dayOfWeek = "Mon", hour = 9)
    @Schedule(dayOfWeek = "Wed", hour = 14)
    @Schedule(dayOfWeek = "Fri", hour = 17)
    public void doPeriodicTask() {
        System.out.println("Performing periodic task...");
    }
}
```
