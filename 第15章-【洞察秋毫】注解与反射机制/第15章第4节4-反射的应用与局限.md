## 4.1 用反射解决开闭原则问题

考虑这样一个场景：有三种水果类，需要根据用户输入的水果名字动态创建对象。

不使用反射的方案：

```java
private static Fruit createFruit(String type) {
    switch (type.toLowerCase()) {
        case "apple":
            return new Apple();
        case "pear":
            return new Pear();
        case "banana":
            return new Banana();
        default:
            return null;
    }
}
```

这个方案的缺点很明显：违反了<font color="red">**开闭原则**</font>（OCP）。如果要增加一种水果（比如Orange），就必须修改`createFruit`方法，再增加一个case语句。

而且以我们之前的知识，没有办法通过一个字符串来创建对象：

```java
String input = "Apple";
Apple apple = new input();    // ❌ 错误
Apple apple = new "Apple"();  // ❌ 没有这样的写法
```

反射可以解决这个问题：

```java
class FruitFactory {
    public static Fruit createFruit(String fruitName) {
        try {
            // 使用反射获取类的Class对象
            Class<?> fruitClass = Class.forName(fruitName);
            
            // 获取类的构造函数
            Constructor<?> constructor = fruitClass.getConstructor();
            
            // 创建对象实例并转换为Fruit接口
            return (Fruit) constructor.newInstance();
        } catch (Exception e) {
            System.out.println("无法创建 '" + fruitName + "' 对象: " + e.getMessage());
            return null;
        }
    }
}
```

这个版本可以根据用户输入的水果单词（字符串），利用反射机制直接生成水果对象。

最大优点是解决了OCP问题：如果需要新增水果种类，只需要添加新的水果类，而不需要修改工厂代码。

## 4.2 反射的适用场景

反射更多是为框架开发者准备的"屠龙技"。在以下场景中合理使用反射：

- <font color="red">**框架开发**</font>：如Spring的依赖注入、JUnit的测试扫描
- <font color="red">**通用工具**</font>：如JSON序列化/反序列化库
- <font color="red">**动态代理**</font>：如AOP（面向切面编程）

在普通的业务代码中，如果能用正常方式实现，就尽量不要用反射。
