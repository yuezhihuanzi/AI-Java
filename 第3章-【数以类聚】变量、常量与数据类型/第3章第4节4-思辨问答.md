## 4.1 为什么变量必须先声明类型？

**问**：老师，为什么 Java 声明变量时必须指定类型？像 `int age = 17` 这种，不能直接写 `age = 17` 吗？

**答**：你去食堂打饭，食堂阿姨看到你拿了一个碗——但如果她不看碗上贴的标签，不知道这个碗是装饭的还是装汤的，她就不知道该给你打什么。

<font color="red">变量的类型就是这个「标签」</font>——告诉 Java 这个变量里存的是什么类型的数据，它才能决定能对这个变量做什么操作。

**问**：那如果我不贴标签呢？

**答**：那 Java 就不知道你是想存数字还是文本。比如你写 `age + 1`：

- 如果 `age` 存的是数字 `17`，那么 `17 + 1 = 18`——年龄加一岁
- 如果 `age` 存的是文本 `"17"`，那么 `"17" + 1 = "171"`——变成字符串拼接

同一个表达式，含义完全不同。Java 选择在<font color="red">**写代码时**</font>就规定好类型，这样一旦你搞混了，它立刻告诉你，而不是等到程序运行到一半才崩溃。这叫做<font color="red">**编译时检查**</font>。

> **核心观点**  
> <font color="orange">提前声明类型不是麻烦，而是 Java 帮你把错误拦截在编译阶段的安全机制。</font>

## 4.2 常量到底是在保护谁？

**问**：老师，定义常量用 `final` 修饰，值就不能改了。但我不改它不就行了吗？为什么非要加个关键字？

**答**：<font color="red">常量不是用来约束你自己的，是用来约束**别人**的——包括未来的你。</font>

假设你写了一个游戏系统：

```java
final int MAX_LEVEL = 100;
```

半年后你再来看这段代码，或者在团队里另一个同事接手了这个项目。他看到 `MAX_LEVEL`，就知道：这个值不应该改。如果他试图给 `MAX_LEVEL` 赋新值，编译器直接报错。

**问**：所以常量是在告诉别人「这个值是特意设计为固定的」？

**答**：对。这和上一节讨论的观点一脉相承——<font color="red">常量是一种**设计决策**</font>。你用 `final` 就是对这个决策做了一个签名：我确定这个值固定不变，请编译器帮我监督。

没有 `final` 的 `int maxLevel = 100`，别人看到会想「这个 100 是随便写的还是精心设计的？能不能改？」有了 `final`，一切不言自明。

> **核心观点**  
> <font color="orange">`final` 不是技术限制，而是你在代码里留下的承诺：这个值是我故意固定的，请不要动它。</font>
