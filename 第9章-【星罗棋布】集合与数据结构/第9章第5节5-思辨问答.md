## 5.1 数组长度为什么要固定

**问**：老师，数组的长度为什么要固定？不能设计成自动扩容的吗？

**答**：这个问题触及了数据结构设计的核心取舍。

数组长度固定，是因为它在内存中需要一块<font color="red">**连续的存储空间**</font>。创建时就确定了这块空间有多大，后续的访问才能做到通过索引一步到位——不管访问第几个元素，花费的时间都一样。

如果允许自动扩容，就面临两个问题：

1. **扩容开销大**：需要找一块更大的连续空间，把原有数据全部搬过去
2. **索引语义不可靠**：元素位置可能会变动

**问**：那我想要自动扩容怎么办？

**答**：用 ArrayList。它底层用的也是数组，但容量不够时会创建更大的数组、复制原有元素，实现「自动扩容」。代价是扩容那一步有性能损耗。

```java
// 数组：长度固定，性能可预期
int[] arr = new int[100];

// ArrayList：长度可变，使用灵活
List<Integer> list = new ArrayList<>();
list.add(1);  // 自动扩容
```

**问**：所以数组和 ArrayList 的取舍是什么？

**答**：本质上是「性能可预期」和「使用灵活」之间的取舍。

- 数据量确定、性能敏感 → 用数组
- 数据量不确定、日常使用 → 用 ArrayList

> **核心观点**  
> <font color="red">数组长度固定不是设计缺陷，而是为了提供可预期的性能。</font> ArrayList 是数组的「灵活版本」，用性能换取便利性。

## 5.2 Set 是怎么做到去重的

**问**：老师，Set 是怎么做到「去重」的？它怎么判断两个元素是不是重复的？

**答**：以 HashSet 为例，它依赖的是对象的 `hashCode()` 和 `equals()` 两个方法。

当调用 `add` 添加一个元素时：

1. **计算哈希码**：HashSet 先计算这个元素的哈希码，根据哈希码决定把它放在内部存储的哪个位置
2. **检查冲突**：如果那个位置已经有元素了，再用 `equals` 方法逐个比较
3. **决定是否添加**：如果 `equals` 返回 true（相等），就拒绝添加；如果不相等，就放在同一个位置的不同槽位里

```java
Set<String> names = new HashSet<>();
names.add("张三");  // 添加成功
names.add("张三");  // 拒绝添加，因为已经存在
```

**问**：那如果自定义类没有重写 hashCode 和 equals 会怎样？

**答**：Set 的去重可能不如预期。

```java
class Student {
    String name;
    int age;
    // 没有重写hashCode和equals
}

Set<Student> set = new HashSet<>();
Student s1 = new Student("张三", 20);
Student s2 = new Student("张三", 20);

set.add(s1);
set.add(s2);  // 可能会添加成功！因为s1和s2的hashCode不同
```

**问**：所以自定义类必须重写 hashCode 和 equals？

**答**：对。如果希望 Set 能正确去重，自定义类必须正确重写这两个方法。

> **核心观点**  
> Set 的去重能力，本质上是 Java 对象自身的相等判断机制在支撑。<font color="red">自定义类必须重写 hashCode 和 equals，否则 Set 无法正确去重。</font>

## 5.3 Map 和 List 什么时候用哪个

**问**：老师，Map 和 List 都能存一堆数据，什么时候用 Map，什么时候用 List？

**答**：判断标准可以归结为一个问题：<font color="orange">**你通过什么方式查找数据**</font>。

**场景 1：按顺序查找**

如果你关心的是「第几个元素是什么」，或者需要按顺序遍历所有元素，用 List：

```java
List<String> names = new ArrayList<>();
names.add("张三");
names.add("李四");

// 按索引访问
String first = names.get(0);  // "张三"

// 按顺序遍历
for (String name : names) {
    System.out.println(name);
}
```

**场景 2：按标识符查找**

如果你关心的是「某个名字对应的值是什么」，通过有意义的标识符而不是数字索引来查找，用 Map：

```java
Map<String, Integer> scores = new HashMap<>();
scores.put("张三", 95);
scores.put("李四", 88);

// 按名字查找
int zhangScore = scores.get("张三");  // 95
```

**问**：那如果既要按顺序，又要按名字查找呢？

**答**：可以组合使用：

```java
// 方案1：List + Map
List<String> order = new ArrayList<>();  // 记录顺序
Map<String, Integer> scores = new HashMap<>();  // 存储分数

order.add("张三");
scores.put("张三", 95);

// 按顺序遍历
for (String name : order) {
    int score = scores.get(name);
    System.out.println(name + ": " + score);
}

// 方案2：LinkedHashMap（保持插入顺序）
Map<String, Integer> scores = new LinkedHashMap<>();
scores.put("张三", 95);
scores.put("李四", 88);
// 遍历时保持插入顺序
```

**问**：所以数据结构不是非此即彼？

**答**：对。数据结构不是非此即彼的选择题，而是可以搭配使用的工具箱。根据业务需求选择合适的组合。

> **核心观点**  
> List 适合「按顺序」的场景，Map 适合「按标识符」的场景。两者可以组合使用，也可以选用 LinkedHashMap 等兼具两者特性的数据结构。
