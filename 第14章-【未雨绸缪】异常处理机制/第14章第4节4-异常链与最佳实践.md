> **阅读指南**  
> 异常不是在出错的地方就地解决就完了——方法一层层调用时，异常会沿着调用链往上抛，最终交给谁处理，直接决定程序能不能恢复。这一节先看清异常在调用链里的传递过程，再总结一套实用的处理原则：什么时候该抛、什么时候该接、什么时候该包装成更有语义的异常，避免把异常处理写成到处try-catch的补丁。

## 4.1 方法调用栈

方法调用栈就是A调用B，B调用C，C再调用D，以此类推，形成调用链条。

```java
public class CallChainDemo {

    public static void methodA() {
        System.out.println("执行方法 A 中的代码...");
        methodB(); // 方法A调用了方法B
        System.out.println("方法 A 执行完毕！");
    }

    public static void methodB() {
        System.out.println("执行方法 B 中的代码...");
        methodC(); // 方法B调用了方法C
        System.out.println("方法 B 执行完毕！");
    }

    public static void methodC() {
        System.out.println("执行方法 C 中的代码...");
        System.out.println("方法 C 执行完毕！");
    }

    public static void main(String[] args) {
        System.out.println("程序开始...");
        methodA();
        System.out.println("程序结束！");
    }
}
```

运行结果：
```
程序开始...
执行方法 A 中的代码...
执行方法 B 中的代码...
执行方法 C 中的代码...
方法 C 执行完毕！
方法 B 执行完毕！
方法 A 执行完毕！
程序结束！
```

`main -> A -> B -> C` 形成了一个调用链。

## 4.2 异常捕获链条

异常的传递路径完全逆着调用链条的路径：

- 方法执行：向下调用（main → A → B → C）
- 异常传递：向上传递（C → B → A → main）

```
    异常传递方向
         ↑
    ┌─────────┐
    │  main   │  ← 最终在这里处理
    │    ↑    │
    │ methodA │  ← 异常经过
    │    ↑    │
    │ methodB │  ← 异常经过（不处理，继续上抛）
    │    ↑    │
    │ methodC │  ← 异常发生地
    └─────────┘
```

就像一个员工（方法C）遇到了自己解决不了的问题，他把问题报告给经理（方法B）。如果经理也解决不了，就报告给总监（A），以此类推。

```java
// 自定义异常
class CustomException extends Exception {
    public CustomException(String message) {
        super(message);
    }
}

public class ExceptionChainExample {
    // 方法3：抛出异常
    static void method3() throws CustomException {
        System.out.println("在 method3 中抛出异常");
        throw new CustomException("这是来自 method3 的自定义异常");
    }

    // 方法2：调用 method3，但不处理异常
    static void method2() throws CustomException {
        System.out.println("method2 调用 method3");
        method3(); // 不处理，异常继续上抛
    }

    // 方法1：调用 method2，并捕获异常
    static void method1() {
        System.out.println("method1 调用 method2");
        try {
            method2();
        } catch (CustomException e) {
            System.out.println("method1 捕获到异常: " + e.getMessage());
        }
    }

    public static void main(String[] args) {
        System.out.println("主方法开始执行");
        method1();
        System.out.println("主方法结束执行");
    }
}
```

## 4.3 最佳实践

1. <font color="red">**精确捕获**</font>：优先捕获具体的异常类型，而不是用`Exception`兜底
2. <font color="red">**不要吞掉异常**</font>：catch块中至少要记录日志，不要什么都不做
3. <font color="red">**异常用于错误处理**</font>：不要用异常控制正常的程序流程
4. <font color="red">**提供有意义的消息**</font>：异常消息应包含足够的上下文信息
5. <font color="red">**优先使用try-with-resources**</font>：简化资源管理
6. <font color="red">**自定义异常继承合适的父类**</font>：根据场景选择`Exception`或`RuntimeException`
