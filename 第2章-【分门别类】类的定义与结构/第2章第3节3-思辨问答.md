## 3.1 类名大驼峰、字段方法小驼峰，这是为什么？

正文提到了命名规范，但你可能好奇：<font color="red">**为什么要这样规定？**</font>

这源于一个认知心理学原理：<font color="red">**通过视觉差异快速区分信息类别**</font>。

```java
class StudentInfo {          // 大驼峰 → 一眼看出是类名
  String studentName;        // 小驼峰 → 一眼看出是变量/方法
  void printInfo() { }
}
```

当你扫视代码时，大小驼峰的差异让眼睛能瞬间区分：

- **类名**（`StudentInfo`）—— 代表一个概念、一个整体
- **字段/方法**（`studentName`、`printInfo`）—— 代表具体的数据或动作

如果违反这个规范：

```java
class studentinfo {          // 全部小写 → 看起来像变量
  String StudentName;        // 大写开头 → 看起来像类名
  void PrintInfo() { }       // 大写开头 → 看起来像类名
}
```

代码能运行，但阅读者的认知负担会大幅增加——需要靠上下文才能判断每个标识符是什么。

**更深层的原因**：Java 诞生时，设计团队参考了当时主流的编程规范（如 C++、Smalltalk），并通过大量实践验证了这套命名约定能显著降低代码维护成本。这不是凭空发明的，而是几十年工程经验的沉淀。

## 3.2 为什么 public 类名必须和文件名一致？

正文提到了一条强制规则：<font color="red">**public 类**</font>名必须与文件名相同。这条规则看起来很奇怪——为什么 Java 要强制这一点？

首先需要澄清一个常见的误解：Java 中只有 **public 类** 才强制要求文件名与类名一致。如果是非 public 类（包私有类），文件名可以和类名不同。

但为什么 public 类要强制呢？这背后有一个工程上的考量：<font color="red">**让代码的「位置」和「身份」保持一致，方便 JVM 找到程序入口**</font>。

```java
// 文件：Cat.java
public class Cat {    // public类，类名必须叫Cat
}
```

当你看到 `Cat.java` 这个文件，你立刻知道里面有一个 `public Cat` 类。当你看到代码里用到 `Cat` 类，你立刻知道应该去 `Cat.java` 里找它。

如果 Java 没有这条规则：

```java
// 文件：Animal.java
public class Cat {    // public类，类名叫Cat，文件名叫Animal
}
```

这会带来什么问题？

- 你想找 `Cat` 类，但不知道在哪个文件里
- 你想看 `Animal.java`，但不知道里面定义的是什么 public 类
- 团队协作时，每个人都要花大量时间「找文件」

**更深层的原因**：Java 诞生于大型团队协作的时代。在没有这条规则的语言（如早期的 C++）中，程序员经常在成百上千个文件中迷失方向。Java 的设计者 James Gosling 和团队总结了这个痛点，决定用强制规则来解决它。

这就像给每个人发身份证：名字必须和本人对应，否则整个社会的管理就会混乱。文件名和 public 类名的一致性，是 Java 代码可维护性的基石之一。
