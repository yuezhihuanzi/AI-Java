## 3.1 什么是包

<font color="blue">**包**</font>是组织 Java 类/接口的命名空间机制，本质是文件系统中的目录结构。

Java 的包系统和操作系统中的文件系统类似，可以有很多子包、子子包。通常，包的最末端是若干个类文件。在 Java 中，每个类都位于一个确定的包中，就像文件系统中每个文件都属于一个目录一样。

## 3.2 package 声明

在 Java 文件首行使用 `package` 关键字声明类所属的包：

```java
// Cat.java位于com/example/mypackage目录下
package com.example.mypackage;  // 包声明必须在文件第一行
```

包具有层级，每层之间用点（.）分隔。包的名字必须对应 Java 文件所在的文件目录：

```
项目根目录/
└── src/
    └── com/
        └── example/
            └── mypackage/
                └── Cat.java
```

类的包名必须与类所在的目录对应（不包括 `src` 目录，这通常作为 Java 项目的源码目录，不计入包级别）。

对于 `Cat` 类，我们称 `com.example.mypackage.Cat` 为<font color="blue">**完全限定名**</font>，而 `Cat` 仅仅是简称。就像人有大名和小名一样，完全限定名是大名，`Cat` 是简化后的名字，为了叫起来方便。实例化对象时也可以使用完全限定名：

```java
com.example.mypackage.Cat cat = new com.example.mypackage.Cat();
```

## 3.3 默认包

对于在 Java 文件顶部有 `package` 声明的包，称为「命名包」。

但一些简单的 Java 示例中，类顶部并没有声明包，Java 也不会报错。如果一个类没有声明所属包，Java 会将这个类划分到<font color="orange">**默认包**</font>中。

所有默认包中的类可以彼此访问，也可以访问默认包以外的类。但反过来，默认包不能被外部包访问。这相当于在默认包周围竖起了结界，外界永远无法进入。

> **最佳实践：永远避免默认包**  
> Java 默认包是一个设计上的隔离区，其中的类几乎无法被包外使用。强烈建议始终为每一个类规划一个有命名的包，这是所有 Java 项目的基础规范。正式项目不可能使用默认包。

## 3.4 物理路径与包路径

「物理路径」通常指 Java 文件在操作系统的完整路径。物理路径同 Java 包的包路径有一定关系，但它们并不相等。

```
C:\projects\my_project\
└── src\
    └── com\
        └── example\
            └── mypackage\
                └── Cat.java
```

包路径总是物理路径中的一段，但包路径并非基于操作系统的盘符开始计算，而是基于 Java 项目下的某个目录（通常是 `src`）开始计算：

```
C:\projects\my_project\src\com\example\mypackage\Cat.java  // 物理路径
C:\projects\my_project   // 项目根目录物理路径
src\com\example\mypackage  // 包路径
com.example.mypackage  // 包名
```

源码目录名也可以自定义，不一定叫 `src`：

```
/my_project/
└── java_code/          # 替代src
    └── com/
        └── example/
            └── mypackage/
                └── Cat.java
```

但大多数情况下，对于小型 Java 项目都会约定俗成地将 `src` 作为源码目录。

## 3.5 包的命名规范

包可以任意命名，但有一些最佳实践经验：

**反向域名确保唯一性**

包名以反向公司/组织域名开头，确保全球唯一：

```java
// 如果你的域名是 example.com
// 项目包名应该以 com.example 开头
com.example.lin.animal
```

由于域名全球唯一，遵循规范就能保证包名不冲突。

**全部小写**

包名全部小写，避免大小写混淆：

```
com.example.util  // 正确
com.Example.Util  // 错误
```

**简洁**

避免冗长，`user.info` 优于 `user.accountmanagement`。

## 3.6 包的作用

为什么需要「包」？

**避免命名冲突**

一个项目由多人协同完成时，很难保证不会出现同名的类。包可以将同名类分布在不同的包中，Java 以完全限定名区分类是否重名：

```
com.example.Cat 和 im.example.Cat 是两个不同的类
```

**逻辑分组**

包可以将功能相关的类组织在一起。将关于动物的类 `Cat`、`Dog`、`Bird` 等都放在 `com.example.animal` 包下，方便管理。

**访问控制**

不同包之间可以隔绝访问，实现类的封装性。

## 3.7 import 导入语句

由于包的存在，一个包的类不知道另一个包中类的存在。`import` 语句用于引入其他包中的类或接口，以便在当前源文件中直接使用它们，无需写出完整限定名。

以 Java 内置的 `ArrayList` 为例：

```java
// 错误!Java不知道ArrayList在哪个包里
ArrayList list = new ArrayList();

// 可以使用完全限定名,但太麻烦了
java.util.ArrayList list = new java.util.ArrayList();

// 使用import预先导入类
import java.util.ArrayList;
// 这样就可以直接使用简单类名
ArrayList list = new ArrayList();
```

`import` 必须位于 `package` 声明之后、类定义之前：

```java
package com.example;      // 包声明
import java.util.ArrayList; // 导入语句
import java.util.List;

public class MyClass { ... }
```

**什么时候不需要 import？**

- 使用 `java.lang` 下的类（如 `String`），该包自动导入
- 使用同一个包中的其他类，无需导入
- 使用类的完整限定名时（不推荐）

---

在 Java 中，一个 `.java` 源文件可以包含多个 `class` 类，但需要遵循严格的规则。核心限制围绕 `public` 类展开。

## 3.8 基本规则

**最多只能有一个 public 类**

一个 `.java` 文件中，最多允许存在一个被 `public` 修饰的类。这个 `public` 类的类名必须与文件名完全一致（包括大小写）：

- 若文件名为 `Hello.java`，则其中的 `public` 类必须是 `public class Hello`
- 若文件名与 `public` 类名不一致，编译时会直接报错

**可以包含多个非 public 类**

除了 1 个 `public` 类，Java 源文件中还可以包含任意多个 `default` 修饰的类（即默认访问权限，无 `public` 修饰）。这些非 `public` 类的类名可以任意，无需与文件名关联。

**若没有 public 类，文件名可任意**

如果 `.java` 文件中没有 `public` 类，则文件名可以是任意名称。

> **最佳实践**  
> 如果没有特殊需要，尽可能保证一个 Java 源文件内部只有一个类且类名与文件名一致。

## 3.9 合法案例

**包含 1 个 public 类 + 多个非 public 类**

```java
// Main.java
// public类,类名与文件名一致
public class Main {
    public static void main(String[] args) {
        System.out.println("主类");
    }
}

// 非public类1
class A {
    // ...
}

// 非public类2
class B {
    // ...
}
```

**没有 public 类（文件名任意）**

```java
// 文件名为Test.java(或AnyName.java)
// 无public类,类名可任意
class C {
    // ...
}

class D {
    // ...
}
```

## 3.10 非法案例

**多个 public 类**

```java
// Demo.java
public class Demo { ... }

// 错误!一个文件中不能有多个public类
public class E { ... }
```

**public 类名与文件名不一致**

```java
// Test.java
// 错误!public类名与文件名(Test.java)不一致
public class MyClass { ... }
```

## 3.11 内部类不受此规则影响

上述规则仅针对<font color="blue">**顶层类**</font>（直接定义在文件中的类）。如果类中包含内部类（如成员内部类、局部内部类、匿名内部类），则内部类的数量和修饰符不受限制，也不会影响顶层类的规则：

```java
// Outer.java
public class Outer {  // 顶层public类,与文件名一致

    // 内部类(可多个,可public)
    public class Inner1 { ... }
    class Inner2 { ... }

    public void method() {
        // 局部内部类
        class LocalInner { ... }
    }
}

class OtherTopClass { ... } // 顶层非public类
```

## 3.12 总结

- 一个 `.java` 文件可包含多个类，但最多 1 个 `public` 顶层类，且其类名必须与文件名一致
- 其他顶层类必须是非 `public` 的
- 若没有 `public` 类，文件名可任意

遵循这些规则是 Java 编译的基础要求。
