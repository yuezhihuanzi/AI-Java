## 5.1 成员变量一定要 private 吗

**问**：老师，书上说成员变量应该都是 private 的。但有些数据我就是想让别人直接读，设为 private 还要写 getter，不是多此一举？

**答**：这个问题很实际。看两段代码：

```java
// 方式1:直接public
public String name;

// 方式2:private + getter
private String name;
public String getName() {
    return name;
}
```

**问**：功能上完全一样啊？

**答**：现在是没区别。但假设有一天，你需要在返回名字之前做点处理，比如去掉前后空格：

```java
public String getName() {
    return name != null ? name.trim() : null;
}
```

如果是 `public` 字段，所有直接访问 `name` 的地方都要改成调用方法。但如果你一开始就用 getter，调用者不需要改一行代码。

**问**：这就是所谓的「留有余地」？

**答**：对。封装的核心思想是：今天你看到的简单读写，明天可能需要加入验证、日志、格式转换。用方法包装起来，未来修改时不会影响调用者。

> **建议**  
> 这不是绝对规则。对于一些内部工具类、测试类，public 字段完全没问题。但对于会被外部使用的类，private+getter/setter 是标准做法。

## 5.2 默认包真的不能用吗

**问**：老师，我写的小测试程序都用默认包，运行得好好的。为什么说默认包不能用？

**答**：默认包不是「不能用」，而是「不能被别人用」。

看一个场景：

```
你的项目:
com.example.app/
├── Main.java
└── ...

一个第三方库:
third.party/
├── Utility.java
└── ...
```

如果 `Utility.java` 在默认包里，`Main.java` 就无法导入它。默认包周围有一道结界，外部进不去。

**问**：那我自己写的项目，所有类都在默认包，总没问题吧？

**答**：确实能跑。但问题在于：

- 你不能使用任何第三方库中的默认包类（虽然正规库不会有）
- 其他项目也不能引用你的默认包类
- 一些构建工具（Maven、Gradle）对默认包支持不好

**问**：所以默认包不是技术限制，而是生态隔离？

**答**：准确说，它是 Java 设计者刻意为之的「玩具区」。正式项目不应该待在玩具区里。

## 5.3 getters 和 setters 必须成对出现吗

**问**：老师，我看到书上 getters 和 setters 总是成对出现。那如果一个数据只能读不能改，是不是只写 getter 就行了？

**答**：当然可以。这其实是封装性的一个典型应用。

```java
class Person {
    private String id;  // 身份证号

    public Person(String id) {
        this.id = id;
    }

    // 只提供getter,不提供setter
    public String getId() {
        return id;
    }
}
```

**问**：这意味着身份证号初始化后就不能改了？

**答**：对。这就是所谓的<font color="blue">**只读属性**</font>。创建对象时通过构造函数赋值，之后外部只能读取，不能修改。

**问**：那为什么不用 `public final String id`？

**答**：效果类似。但 `final` 的字段在对象创建后就永远不能改，连类内部都不能改。而 `private + getter` 的方式，类内部的方法仍然可以修改：

```java
class Person {
    private String id;

    // 类内部可以修改
    void correctId(String newId) {
        // 身份证号勘正逻辑
        this.id = newId;
    }

    // 外部只能 read
    public String getId() {
        return id;
    }
}
```

**问**：所以 private 比 final 更灵活？

**答**：灵活程度不同。`final` 是绝对的不可变，`private + getter` 是「对外只读，对内可控」。根据场景选择。

## 5.4 封装会不会过度

**问**：老师，如果每个字段都要写 getter 和 setter，一个类动不动就上百行。会不会过度封装？

**答**：你的直觉是对的。封装确实有成本。

如果一个类纯粹是数据载体，不需要任何验证和转换逻辑，可以考虑使用<font color="blue">**记录类**</font>（Record，Java 14+ 引入）：

```java
public record Person(String name, int age, String id) { }
```

一行代码，编译器自动生成构造函数、getter、equals、hashCode 等方法。但它不可变——创建后不能修改。

**问**：那如果需要可变的数据载体呢？

**答**：那就老老实实写 getter 和 setter。或者借助 IDE 的自动生成工具，不需要手写。封装的成本没有你想的那么高。

> 好的 IDE（如 IntelliJ IDEA）可以一键生成所有 getter 和 setter，成本几乎为零。
