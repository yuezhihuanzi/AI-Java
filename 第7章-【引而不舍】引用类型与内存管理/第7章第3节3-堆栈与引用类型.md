## 3.1 Java 内存管理基础

我们首先从最简单的基本类型来探讨下 Java 变量的存储与引用方式。看一个示例：

```java
int a = 5;
```

虽然我们都知道，上述代码表示定义一个变量 `a`，它的值等于 5。但这只是 Java 这个魔术师将复杂的底层细节屏蔽掉了，给了我们一个简单的语法。

我们有必要了解下这里面的一些底层细节。

```java
int a = 5;
System.out.println(a); // 打印：5
```

当定义了变量 `a` 后，后续再次使用 `a`，将返回数字 5。所以，`a` 就像是 5 这个数字的名字，通过这个名字可以找到数字 5。

无论代码多么复杂，只要以后使用变量 `a`，都可以返回数字 5：

```java
int a = 5;
System.out.println(a); // 打印：5
int b = 3 + a;  // b = 8
int c = 5 / a ; // c = 1
```

那如果我们稍微追问一下，为什么使用变量 `a` 就能返回数字 5？理解这个过程对于程序员（不只是 Java 程序员，主流编程语言其实这里的机制几乎是一样的）非常重要。

以下内容涉及一些计算机基础原理，但理解起来并不难，即使没有计算机基础也可以理解。

```java
int a = 5;
```

当写下上述代码后，Java 需要有一个地方存储数字 5，且需要记住这个数字 5 的存储位置，方便以后能够通过变量 `a` 找到这个数字。那么问题来了，Java 将这个数字 5 存储在哪里？

Java 程序在运行时会将变量的实际值存储在计算机内存里。但 Java 对内存的利用并不会那么简单，实际上 Java 会将内存分为<font color="blue">**堆**</font>（Heap）和<font color="blue">**栈**</font>（Stack），也就是说 Java 并不会傻傻的直接就将数据丢到内存里，而是会精细化的管理内存，并存储运行时的各种数据。

之所以需要搞这么复杂，原因也很简单，数据并不会只有类似于上述案例的这种简单的数字 5。想想我们已经接触到的数据类型，有整数、浮点数、字符串、布尔值、还有对象，未来我们还要学习接口、数组、字典等更多的数据类型。

这么多的数据类型，如果不对内存做复杂的精细化管理，而是一股脑的丢到内存中，这倒不是不可以。但我们需要考虑的一个问题是，计算机的资源尤其是内存的资源是非常稀缺的。没有精细化的管理就无法对内存高效地利用。打个比方，本来 1G 内存通过精细化管理可以装十万个数据，但是不做管理而是随意写入数据，可能只能装一万个。

容量变小了怎么办？那就只能花钱堆硬件，将原来 1G 的内存升级到 10G。

当然，在偏编程的书籍里想完全吃透内存管理不太现实，但我们可以初步了解下 Java 是怎么优化内存存储的。

## 3.2 栈（Stack）

栈本身是一种数据结构，具有后进先出（LIFO）的特性。

但我们这里说的 Java 中的栈，不能简单理解为一种数据结构。它实际上是 Java 虚拟机管理的一块内存区域，只是应用了栈这种数据结构。

当然，我们可以不关注这些细节，只需要知道 Java 将哪些类型的数据存储在栈中。

回到之前提出的问题：

```java
int a = 5;
```

这里的 5 究竟存储在哪里？答案是不确定。我们先来假设一种简单的情况：

```java
void sampleMethod(){
  int a = 5; // 局部变量
  System.out.println(a);
}
```

假设 `int a = 5` 出现在方法中，此时 `a` 被称为<font color="blue">**局部变量**</font>。相对于「局部变量」来说，还有一类变量是我们熟悉的「成员变量」：

```java
class Cat{
  int a = 5; // 成员变量
}
```

对于局部变量和成员变量，Java 存储它们的位置是不同的。如果是局部变量 `a`，它实际存储在栈中，具体来说是存储在栈的局部变量表中。

但如果 `a` 是「成员变量」，则并不会存储在栈中，而是会随对象存储在堆中。这一点我们后续会讲解。

不只是 `int` 型变量，当局部变量是 8 种基本类型时，都将存储在栈中。

```java
void sampleMethod(){
  int a = 5;          // 局部变量，存储在栈中
  double b = 8.0;     // 局部变量，存储在栈中
  boolean c = false;  // 局部变量，栈中
  String s = "Lily";  // String 不是基本类型，不在栈中
}
```

## 3.3 堆（Heap）

除了基本类型，Java 还有引用类型，那么引用类型是存储在哪里的？我们用实际的代码来举例说明：

```java
class Cat{
  int age;         // 成员变量
  double height;
  Cat(int age, double height){
    this.age = age;
    this.height = height;
  }
}
```

上述代码是一个典型的类，我们将这个类实例化：

```java
Cat cat = new Cat(1,2.2);
```

上述代码得到了一个 `cat` 变量，这个变量的类型是 `Cat` 类，而对象是典型的引用类型。我们现在探讨的问题是对于 `cat` 这个对象，它存储在哪里？是栈吗？

不是，Java 的引用类型是存储在「堆」中的，而不是「栈」中。我们要意识到，不同于基本类型，引用类型的结构要比基本类型复杂很多，比如对象，它是一个复杂的结构，有方法、还有成员变量：

```java
class Cat{
  int age;           // 成员变量
  double height; 
  Person person;     // 成员变量也可以是另外一个对象
  Cat(int age, double height){
    this.age = age;
    this.height = height;
  }
  void meow(){
    int a = 3;
    System.out.println("Meoooow");
  }
}
```

对于较为复杂的引用类型，Java 会选择将其放在「堆」中。注意上述代码中的成员变量，`age` 和 `height`，这两个是基本类型，之前我们谈到过，基本类型如果是作为局部变量，那么它是存储在「栈」中的。但基本类型如果作为成员变量呢？是存储在「栈」还是「堆」中呢？

答案是：<font color="red">**成员变量即使是基本类型也会随对象一起存储在「堆」中，而不是栈中**</font>。

上述代码中，只有 `meow()` 方法中的局部变量 `a` 是存储在「栈」中的，其他成员变量都随对象一起存储在「堆」中。

## 3.4 寻址问题

存储的问题我们差不多讨论清楚了，这里总结一下 Java 堆和栈的差异：

| 特性 | Java 堆 (Heap) | Java 栈 (Stack) |
|------|---------------|----------------|
| 存储内容 | 对象实例本身、数组 | 基本类型局部变量、对象引用、方法参数、返回地址等 |
| 共享性 | 被所有线程共享 | 每个线程私有 |
| 生命周期 | 对象的生命周期由 GC 管理，与引用无关 | 内存随方法调用开始分配，调用结束自动释放 |
| 内存管理 | 动态分配，自动 GC 回收，可能发生 OOM | 自动分配和释放（LIFO），一般不会 OOM |
| 访问速度 | 相对较慢（需要指针寻址） | 相对较快（位于 CPU 缓存/寄存器附近） |
| 大小 | 较大，可配置（`-Xms`, `-Xmx`） | 较小（`-Xss` 配置线程栈大小） |
| 错误 | OutOfMemoryError: Java heap space | StackOverflowError |

上述表格给出了 Java 堆和栈完整的区别，目前我们只需要关注「存储内容」这一项，其他的区别可以在同学们有一定基础后再比较。

简单来说：<font color="orange">堆是放「东西」（对象）的大仓库，由专人（GC）负责打扫清理；栈是放「地址条」（引用）和「小零件」（基本类型）的临时工作台，用完自己就清空了。</font>

虽然存储的问题已经讨论完毕，但我们还需要了解一下「寻址」的问题。对象确实已经存储在了「堆」里，但 Java 怎么找到这个对象呢？类比下生活里的常识：

你有一幢房子，但你朋友怎么找到你的房子呢？生活中，我们会用门牌号来标记一幢房子，只要你的朋友有门牌号的完整的地址，就能找寻到你。

其实存储在堆里的对象也是一样，它需要有一个地址来寻找到它。

我们来用一个例子解释下这个过程（它并不严谨，但它能帮助我们理解这个过程）：

当你写 `Cat c = new Cat();` 时，发生了两件事：

**在仓库（堆）里造东西**：`new Cat()` 在堆里划出一块地方，创建了一个 `Cat` 对象（包含它的年龄、身高等数据）。

**给你一个地址**：由于这个地址比较简单，所以这个地址并不会存储在「堆」里，而是放在「栈」里，它的目的是为了寻找到「堆」里的对象。

关键点：

- 你手里的变量名 `c`，只是一个地址，不是对象本身。
- 地址 `c` 很小，可以轻松放在栈上，你可以通过 `c` 这个变量来找到对象。
- 真正的对象很大，只能放在仓库里（堆里）。

最后我们来总结下：

- 对于基本类型，如果它是局部变量，则 Java 会将局部变量的值直接存储在「栈」中，通过变量即可获取到这个局部变量的值。
- 对于对象，它本身位于「堆」中，必须有一个位于「栈」中的地址才能找到这个对象。

## 3.5 元空间（扩展阅读）

还有一个问题，类和方法的代码存储在哪里？

类和方法既不存储在「栈」中，也不存储在「堆」中，而是存储在一个叫做「<font color="blue">元空间</font>」的地方。「元空间」同「栈」、「堆」有非常大的区别。

相对于堆和栈主要用来存储数据，元空间的主要作用不是用来存储数据的。元空间主要是用来存储一些描述类信息（也称为元信息）。首先我们直观的来看下「数据」和「方法」有什么区别，为什么 Java 会区别对待这两个东西：

```java
int a = 5; // 数据

// 方法
void meow(){
  System.out.println("Meooooow");
}
```

数据是表示一个现实里的数值，它通常较为简单，所以 Java 往往也只需要存储这些数值即可。比如上述代码就只需要存储 5 这个数字。

但方法并不是为了表示数值，方法主要是一组代码（第 4 到第 6 行，某些方法的代码常常有几十行），存储这些代码和存储一个数值肯定需要不同的存储方式。

比如，方法就需要记录：

- 方法名称
- 返回类型（包括泛型信息）
- 参数列表（数量、类型、顺序、泛型信息）
- 访问修饰符
- 方法的字节码指令（bytecode）本身就存储在这里
- 方法的异常表

类也是一样，通常它需要记录：

- 类名、全限定名
- 直接父类的全限定名（`java.lang.Object` 除外）
- 类型（类、接口、枚举等）
- 访问修饰符（`public`, `abstract`, `final` 等）
- 实现的接口列表

上述有一些内容（诸如泛型、父类、访问修饰符、异常、接口等）我们需要在后面章节中学习，但从上述内容我们可以知道，无论是类还是方法都需要存储大量的不同于简单数据的相关信息。

所以，Java 编译器并不会选择用「堆」和「栈」来记录这些信息，每种数据结构都有其适合存储的内容，而「堆」和「栈」不适合存储方法和类的元信息。那 Java 怎么记录方法和类的这些元信息？

Java 选择用「元空间」来记录上述方法和类的相关信息。

这里简单解释下什么是「元」（Meta）。「元」这个概念无论在 Java 还是 Python 中都有出现。但这个概念确实不好理解，它非常抽象。

「元」通常表示「更高一层的抽象」。想象一个金字塔结构，每一层都在描述或定义它下面一层：

- **基础层**（你操作的具体事物）：数据、对象、函数、类...
- **元层**（描述/定义基础层的事物）：元数据、元类、元信息...
- **元元层**（描述/定义元层的事物）：（较少见，但理论上存在）
- ......（如果有需要，可以无限堆叠下去）

「元」的核心意义就是：描述、定义、控制它下面那一层结构的东西。它站在一个更高的抽象层次上，观察和操纵底层的元素。我们拿乐高说明书比喻：

- **拼好的乐高模型**（基础层）：一个具体的城堡、飞船。这就是你的程序运行时的「对象」。
- **乐高说明书**（元层）：说明书告诉你需要哪些零件（类定义中的成员变量）、这些零件怎么拼装在一起（类定义中的方法、构造函数）、最终拼出来是什么样子（类的结构和行为）。说明书描述了如何构建模型，它本身不是模型。
- **设计说明书的设计规范**（元元层 - 可选）：如果有一套规则规定「乐高说明书应该怎么写」（比如必须有哪些步骤、用什么图示），那么这套规则就在描述「说明书」这个层次的东西，可以看作是元元层（Python 中有一个东西叫「元类」可以理解为是创造类的类，其实就是元元层）。

所以，你看，「元」就是上一层对于下一层的指导，就是这个意思。

如果扩展「元」的概念，就会出现「元数据」表示「描述数据的数据」、「元信息」表示「描述信息的信息」。

Java 的「元空间」，其实就是用来管理各种 Java 里的元信息或者元数据的地方，这里面最典型的就是需要把类和方法的元数据保存起来。无论是类的名字还是方法的名字、参数列表，其实都是对于类和方法的描述，它们自然应该保存在元空间里。

## 3.6 引用类型的定义

铺垫了这么多，我们现在来总结一下引用类型。

在 Java 中，<font color="blue">**引用类型**</font>（Reference Types）是面向对象编程的核心，与基本类型有本质区别。引用类型不直接存储数据本身，而是存储对象在堆内存中的地址。

```java
String str = "Hello";     // str 存储字符串对象的引用
Cat cat = new Cat();      // cat 存储新建对象的引用
```

- **存储内容**：对象在堆内存中的内存地址
- **实际对象**：存储在堆内存中

如果在定义引用类型时不给它赋值，则默认值为 `null`（空值）。`null` 表示不指向任何对象：

```java
class Cat{
  int age;        // 如果没有赋值，默认为 0
  double height;  // 如果没有赋值，默认为 0.0d
  String name;    // 如果没有赋值，则默认是 null
}
```

我们之前有谈到过，仅当变量是成员变量时才会被自动分配默认值；如果是局部变量，不会被分配默认值：

```java
void meow(){
  String s; 
  System.out.println(s); // 会报错，这是局部变量，必须进行初始化赋值
}
```

## 3.7 引用类型的判等问题

有时候我们会判断两个变量是否相等，比如两个人的年龄是否相等？用我们之前学习的知识：

```java
int age1 = 18;
int age2 = 18;
boolean isEqual = age1 == age2; // isEqual = true，所以相等
```

基本类型的判等都好理解，就是简单的比较两个值是否相等。但对于引用类型来说判断是否相等是一个较为复杂的问题。

我们用两个引用类型来测试下：

```java
String s1 = new String("hello");
String s2 = new String("hello");

boolean isEqual = s1 == s2; 
```

同学们可以猜一下，上述代码中的 `isEqual` 是 `true` 还是 `false`？看起来两个字符串 `s1` 和 `s2` 的值都是 `"hello"`，所以应该是 `true` 判断为相等。

但事实是，`isEqual` 的值会被判断为 <font color="orange">`false`</font>，不相等。这就是引用类型和基本类型的区别。

导致判断为 `false` 原因在于，引用类型比较的是对象的内存地址（结合之前探讨的寻址知识来理解）：

```java
String s1 = new String("hello"); // 生成一个对象，将对象地址赋值给 s1
String s2 = new String("hello"); // 又生成一个，将对象地址赋值给 s2
```

这两个对象，虽然字符串值都是 `"hello"`，但问题是它们是两个不同的对象，它们的内存地址不可能相同。所以：

```java
boolean isEqual = s1 == s2; // 比较的是两个对象的内存地址，自然不同
```

但我们可以看到上述两个 `String` 类型的变量，它们的字符串值确实是 `"hello"`，怎么能够判断这两个对象的内容是相等的，而不是比较它们的地址呢？

可以使用 `equals` 方法来进行比较。每个对象下面都会有一个 `equals` 方法，这是 Java 默认具有的方法（后面我们学习 Java 的继承时就会理解，现在先暂时认为对象下都有这个方法）：

```java
String s1 = new String("hello");
String s2 = new String("hello");
boolean isEqual = s1.equals(s2); // true（内容相同）
```

我们把这个示例扩展下：

```java
String s1 = new String("hello");
String s2 = new String("hello");
String s3 = s1; 

boolean isEqual = s1==s2;          // false，s1 和 s2 的地址不同，不相等
boolean isEqual1 = s1==s3;         // true, 由于 s1 和 s3 都指向同一个对象(地址相同)
boolean isEqual2 = s1.equals(s2);  // true，比较的是内容而不是地址
```

### 自定义对象的 equals 问题

当然，引用类型不只是 `String` 这种内置的对象，还有我们的自定义对象：

```java
class Cat{
  int age;
  double height;
  Cat(int age, double height){
    this.age = age;
    this.height = height;
  }
}

Cat cat1 = new Cat(18, 2.0);
Cat cat2 = new Cat(18, 2.0);
boolean isEqual = cat1 == cat2;
boolean isEqual1 = cat1.equals(cat2);
```

请问上述 `isEqual` 和 `isEqual1` 的值分别是什么？答案是<font color="orange">两个都是 `false`</font>。

对于 `cat1 == cat2` 的判断，我们可以理解它是 `false`，因为这比较的是两个不同对象的地址。但为什么用 `equals` 比较也是 `false` 呢？

明明这两个对象的成员变量都是 18 和 2.0，内容完全一样，理应是 `true` 才对。要理解这一点，还需要学习更多的知识，我们这里先简单解释一下。

默认情况下，对于自定义对象，它的 `equals` 方法比较的也是两个对象的地址，而非内容。所以如果不做一些处理，以下两个比较是等价的，没区别：

```java
boolean isEqual = cat1 == cat2;
boolean isEqual1 = cat1.equals(cat2); // 实际上还是在比较对象的地址
```

如果要解决这个问题，想让 `equals` 比较内容而不是引用地址，那么需要重写 `equals` 方法。重写技术需要等到我们学习类的继承后才能理解，这里先放一下。
