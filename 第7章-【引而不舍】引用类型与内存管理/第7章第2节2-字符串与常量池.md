> **阅读指南**  
> 字符串是 Java 里使用最频繁的引用类型，也是初学者最容易踩坑的地方。这一节先讲清楚字符串的两种创建方式——字面量和 `new`——它们看起来一样，背后的对象却可能完全不同；顺着这个差异，我们会看到常量池机制：字面量会被复用，`new` 出来的对象各占一份内存。理解了这一点，「为什么两个内容相同的字符串用 `==` 比较却是 `false`」这类问题就迎刃而解，字符串拼接该不该用 `StringBuilder`，也会自然有答案。

## 2.1 字符串的创建方式

Java 变量除了 8 种基本类型外，还有一类广泛应用的类型——<font color="blue">**引用类型**</font>（Reference Type）。引用类型与基本类型在计算机存储内容、内存管理方式、赋值方式上有很大的不同。

而字符串是 Java 中使用最多的一种引用类型。它通常用来表达现实世界里的文本数据，比如一首宋词、一封信的内容，均可以用字符串来表达。

创建一个字符串有很多种方式，这里介绍使用最多的两种。

### 字面量赋值

```java
String s = "Java"; // 这种直接给出字符文本的方式，我们称为字面量赋值方式
```

### 通过字符串类实例化

```java
String s = new String("Java");
```

`String` 实际上是一个类，可以通过 `new` 关键字实例化一个字符串对象。在实例化时，通过构造函数可以传入字符串实际值。比如上述示例就传入了 `"Java"` 这组文字。

## 2.2 字面量（Literal）

<font color="blue">**字面量**</font>是直接在源代码中表示固定值的语法表示形式。它们是程序中直接写出的原始数据值，无需通过变量或计算获得。Java 主要字面量如下：

```java
String s = "Hello World";  // 双引号内的内容是字符串字面量
long d = 100L;             // long 类型字面量（L 后缀）
boolean t = true;          // 布尔类型字面量
```

## 2.3 字符串拼接

字符串最基本的操作是多个字符串进行拼接。最常用的拼接方法是使用 `+` 号运算符（`+` 既可以用于算术运算也可以用于字符串）。

```java
String s1 = "Hello";
String s2 = "World";
String s3 = s1 + s2;       // s3 = "HelloWorld"
String s4 = "My name" + "is Lily"; // s4 = "My nameis Lily"
```

使用 `+` 运算符虽然简单，但在大量字符串多次拼接的运算中，`+` 运算符效率非常低。所以如果是频繁拼接字符串，建议使用 `StringBuilder` 类：

```java
StringBuilder sb = new StringBuilder(); // 实例化 StringBuilder 对象
sb.append("姜磺");         // 调用 StringBuilder 对象的 append()方法
sb.append("是");
sb.append("一只");
sb.append("猫");
// 调用 StringBuilder 的 toString()方法
// result = "姜磺是一只猫"
String result = sb.toString();  
```

> **什么时候使用 StringBuilder？**  
> 当大批量频繁拼接字符串的时候建议使用 `StringBuilder`。比如需要连续拼接字符串 10000 次、1000000 次，拼接数量越多越应该使用 `StringBuilder`，因为 `StringBuilder` 的字符拼接效率远比 `+` 运算符要快。如果只是 3 次、5 次拼接字符串，两种方案都可以。`+` 运算符虽然性能不及 `StringBuilder`，但它胜在可读性更好。

## 2.4 字符串常见方法

字符串除了经常需要拼接外，还需要用各种方法进行处理。由于字符串 `String` 本身是一个类，所以它可以包含很多方法。常用的方法有以下若干（不完全）：

| 方法 | 功能 | 示例 |
|------|------|------|
| `length()` | 字符串长度 | `"abc".length()` → 3 |
| `charAt(int)` | 获取指定位置字符 | `"Hello".charAt(1)` → `'e'` |
| `substring(int, int)` | 截取子串 | `"Hello".substring(1,3)` → `"el"` |
| `replace(char, char)` | 字符替换 | `"Java".replace('a', 'o')` → `"Jovo"` |
| `toLowerCase()` / `toUpperCase()` | 大小写转换 | `"Java".toUpperCase()` → `"JAVA"` |
| `trim()` | 去除首尾空格 | `" Java ".trim()` → `"Java"` |
| `split(String)` | 按分隔符拆分 | `"a,b,c".split(",")` → `["a","b","c"]` |
| `join(CharSequence, Iterable)` | 连接字符串 | `String.join("-", "A","B")` → `"A-B"` |

以上列出的是编程语言中使用频率最高的字符串方法，但并不是全部的方法。实际上字符串相关的方法数量非常多。这里并不建议同学们死记硬背这些方法。

当我们需要处理一个字符串时，如果你记得某个方法可以处理那么就直接使用；如果不记得，应该利用搜索引擎或者 AI 大模型来查找是否有需要的方法。死记硬背这些方法没有任何意义。

### substring 方法的端点问题

这里还有一个问题，我们举例说明。

如果有一个字符串 `"Javaooo"`，但我需要的是 `"Java"`，所以需要去掉 `"ooo"`，那么怎么处理？参考下面的示例：

```java
String s = "Javaooo".substring(0,4); // s = "Java"
```

`substring()` 方法可以获取字符串的部分子串，它可以接收两个参数，分别是子串起始位置序号和终止位置序号。我们需要获取 `"Java"` 这个子串，所以序号为 0、4。

这里需要解释下，为什么是 0 和 4。起始位置是 0，而不是 1，是因为几乎所有主流编程语言（除了 MATLAB 和 Lua 等语言）序号一般都是从 0 开始而不是 1。那么为什么终止序号是 4 而不是 3，这就涉及到一个普遍的端点问题。

在 Java 中，涉及到序号端点问题一般遵循规律 <font color="red">**「左闭右开」**</font>，即包含左端点，而不包含右端点。所以 0 到 3，实际上不包含 3，只取 0、1、2。这样实际上只能取到 `Javaooo` 的前三个字符 `J`、`a` 和 `v`。如果要完成目标，需要指定 0 到 4，才能获取到 `J`、`a`、`v` 和 `a` 这四个字符。

### 字面量调用方法的原理

第二个问题，上述代码中我们使用的是 `"Javaooo".substring(0,4)`，这里通过字面量 `"Javaooo"` 来调用方法 `substring()`，这就有些奇怪。

`substring()` 是一个方法，在我们目前的认知里，只有对象下面才有方法可以调用。如果是下面的写法可能才符合我们的认知：

```java
String s = new String("Javaooo"); // 实例化字符串对象 s
String s1 = s.substring(0,4);     // 调用对象下的 substring 方法
```

那为什么可以直接写成字面量形式 `"Javaooo".substring(0,4)`？

在 Java 中，字符串字面量（如 `"Javaooo"`）本质上就是 `String` 对象，这是允许你直接在字面量上调用字符串方法的关键原因。我们可以尝试简单解释下这里面的「小魔法」：

当你在代码中写 `"Javaooo".substring(0,4)` 时，Java 编译器会创建一个 `String` 对象来表示 `"Javaooo"` 这个字面量，这个字面量会被存储在<font color="blue">**字符串常量池**</font>（String Pool，后续我们会介绍字符串常量池）。

所以其实 `"Javaooo"` 字面量在调用方法时等价于 `new String("Javaooo")`：

```java
// 你写的代码
String s = "Javaooo".substring(0,4);

// 编译器实际处理
String temp = new String("Javaooo"); 
String s = temp.substring(0,4);
```

如果有可能，建议尽量使用字面量的方式来调用方法，虽然字面量在调用方法时类似于 `new String()`，但实际上编译器会对这个过程进行优化，效率上字面量要更高一些。当然，这个优化也是利用了之前我们谈到的「常量池」。

## 2.5 字符串常量池机制

先看一段代码：

```java
String s1 = "hello";
String s2 = "hello";
boolean isEqual = s1 == s2; 
```

请问上述代码中的 `isEqual` 是 `true` 还是 `false`？根据前面的知识，因为 `==` 比较的是对象的地址，所以我们会认为 `isEqual` 的值是 `false`。

抱歉，这里 `isEqual` 实际值是 <font color="orange">`true`</font>，而不是 `false`。这有点违反我们的理解。

在本章开头创建字符串的小节，我们讨论过两种不同的字符串创建方式：

```java
String s1 = "hello";          // 字面量创建
String s2 = new String("hello"); // String 对象实例化
```

这两种不同的方式，Java 在底层处理时差异性非常大。`new` 的方式每次都会创建一个独立的 `String` 对象：

```java
String s1 = new String("hello");
String s2 = new String("hello");
```

`s1` 和 `s2` 是完全不同的两个 `String` 对象。

分析下这样做的缺点是什么：虽然两个字符串的内容都是 `"hello"`，但它们却是两个不同的对象。这在创建少量字符串时没有问题，但如果创建 10000 个相同内容的字符串，用 `new` 的方式显然非常浪费计算机的资源。因为 10000 个 `"hello"`，本身没有区别，却需要创建 10000 个 `String` 对象。

那能不能让内容相同的字符串共用一个字符串对象呢？比如 10000 个 `"hello"` 都共用 1 个对象？答案是可以：<font color="red">**字面量创建字符串的方式就可以解决这个问题**</font>。

字面量创建的字符串同 `new` 创建的 `String` 对象有一些不同。当使用字面量的方式创建字符串时，Java 会首先到一个被称为「<font color="blue">**字符串常量池**</font>」的地方寻找是否有相同的字符串，如果有则直接返回这个字符串的引用；而如果没有，则会在堆中创建一个字面量对象，然后将这个对象的引用放在字符串常量池中。下次如果有相同的字符串被创建时，直接会返回常量池中的引用。

很显然上述的机制会保证无论有多少个字符串，只要它们字面量相同，就只有一个字面量对象，所有字符串共享一个对象。

## 2.6 常量池工作流程

在理解这个机制后，我们再来看看之前的问题：

```java
String s1 = "hello";
String s2 = "hello";
boolean isEqual = s1 == s2; // isEqual = true
```

当第一次创建 `"hello"` 字符串时，常量池中没有这个字符串的引用，Java 随即在堆中创建一个 `"hello"` 字符串的字面量对象，随后将这个字面量对象的引用（地址）放在常量池中。

当第二次创建 `"hello"` 字符串，即 `s2` 时，由于常量池中已经存在 `"hello"` 的地址，则直接将这个地址返回给 `s2`。

所以实际上无论是 `s1` 还是 `s2` 都是同一个地址，它们自然是相等的。

上述关于字符串的知识，是 Java 面试中非常高频的面试问题。理解这个知识点对于 Java 程序员来说非常的重要。

## 2.7 性能对比

这里给出一组字面量创建字符串和 `new String` 创建字符串的计算机性能消耗对比（测试环境 JDK17）：

| 方式 | 1000 万次耗时 | 内存分配压力 |
|------|--------------|-------------|
| 字面量对象 | 120 ms | 极低 |
| 实例化 String 对象 | 860 ms | 高 |

很显然，字面量的方式速度更快，内存占用更小。没有特殊原因，我们应该优先选择用字面量的方式创建字符串，只有极少数的场景下才需要使用 `new String` 的方式创建字符串（比如需要独立的字符串实例时）。
