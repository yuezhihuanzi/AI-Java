## 4.1 为什么需要抽象类

在面向对象编程中，经常会遇到一种情况：我们知道一个类应该存在，也能明确它的一部分行为和属性，但无法或不应该去完整地实现它。

一个经典例子：图形(`Shape`)。

假设我们有一个"图形"体系，包含"圆形"、"矩形"等具体图形。这些图形都有一个共性：

- 所有图形都应该有"计算面积"和"计算周长"的行为

但是，"图形"本身是一个过于抽象的概念，因为它并没有表明到底是什么图形。我们无法为一个"图形"提供"计算面积"和"计算周长"方法的具体实现，因为不知道它具体是什么形状。

> <font color="red">**关于"抽象"这个词**</font>  
> 很多编程初学者觉得"抽象"很难理解，那你可以暂时将其理解为"不确定的、模糊的"。

首先看看，用现有知识，"图形"类应该怎么表达：

```java
class Shape {
    private String color;

    // 方法 - 没有实现(空方法,因为不知道怎么实现)
    // 留在这里等子类去重写
    public double calculateArea() { };
    public double calculatePerimeter() { };

    // 普通方法 - 有具体实现
    public String getColor() {
        return color;
    }

    public Shape(String color) {
        this.color = color;
    }
}
```

上述定义有什么缺点？

`calculateArea()`和`calculatePerimeter()`是违反语法规则的。由于规定了返回类型是`double`,所以方法体不能为空，必须有`return`语句。当然可以修改成返回`0.0`:

```java
public double calculateArea() { return 0.0; };
```

但这样做不好。因为这很容易让人以为这个图形计算周长和面积的结果就是`0.0`。但实际上我们只是不知道怎么实现这个方法，所以想暂时"留白"不去实现，等待子类去实现。如果返回`0.0`,没有体现出这个意思。

上述`Shape`是可以被实例化的。但`Shape`类实例化后是有问题的——调用`calculateArea()`会返回`0.0`,这个结果会让人困扰。其实这种方法根本就不应该在`Shape`里被调用，它们只是用来强调：子类啊，你一定要重写我，写出具体的计算面积和周长的方法。

那我们希望实现怎样的目的？

- 我们希望`Shape`不要被实例化，就老老实实作为基类，去定义一些子类必须拥有的属性和方法即可
- 要求继承`Shape`的所有子类都必须实现(重写)计算面积和计算周长的方法

## 4.2 抽象类与抽象方法

怎么解决以上两个问题？答案是用<font color="red">**抽象类**</font>和<font color="red">**抽象方法**</font>。

所谓"抽象"即它不是真实的，也不能直接被使用。它需要被子类来具体实现。举个现实的例子：

> 领导往往会提出一些战略性的目标，这些目标不是具体的，只是指导性的。但是具体怎么操作怎么实现需要成员们自己拿出具体的方案。

可以使用`abstract`关键字定义抽象类和抽象方法：

```java
abstract class Shape {
    // 可以包含属性、普通方法、抽象方法、构造方法等
}

// 抽象方法后面不能够有大括号{}
public abstract double calculateArea();
public abstract void draw(String color);

// 错误!抽象方法不能有主体
public abstract void method() { }  // 编译错误

// 错误!普通类中不能有抽象方法
class ConcreteClass {
    public abstract void method();  // 编译错误
}
```

务必理解`abstract`的作用：它表明我是抽象的，我不是具体的，想要具体的去我的子类里面找。

## 4.3 子类如何实现抽象方法

用`abstract`来重新编写`Shape`类：

```java
abstract class Shape {
    private String color;

    // 抽象方法 - 没有实现
    public abstract double calculateArea();
    public abstract double calculatePerimeter();

    // 普通方法 - 有具体实现
    public String getColor() {
        return color;
    }

    public Shape(String color) {
        this.color = color;
    }
}
```

子类如何实现抽象类的方法：

```java
// 非抽象子类Circle,必须实现所有抽象方法
class Circle extends Shape {
    private double radius;

    public Circle(String color, double radius) {
        super(color); // 调用父类构造方法
        this.radius = radius;
    }

    @Override
    public double calculateArea() {
        return Math.PI * radius * radius;
    }

    @Override
    public double calculatePerimeter() {
        return 2 * Math.PI * radius;
    }
}

// 非抽象子类Rectangle
class Rectangle extends Shape {
    private double length;
    private double width;

    public Rectangle(String color, double length, double width) {
        super(color);
        this.length = length;
        this.width = width;
    }

    @Override
    public double calculateArea() {
        return length * width;
    }

    @Override
    public double calculatePerimeter() {
        return 2 * (length + width);
    }
}
```

子类必须实现`Shape`父类的所有抽象方法，如果不实现，代码将无法通过编译。

## 4.4 抽象类的使用规则

<font color="red">**抽象父类的规则**</font>:

- <font color="red">**抽象类不能被实例化**</font>:不能使用`new`关键字来创建一个抽象类的对象(如`new Shape()`是非法的)
- <font color="red">**只有抽象类可以包含抽象方法**</font>:这是抽象类与普通类最显著的区别
- <font color="red">**抽象类也可以包含普通类拥有的一切成员**</font>:普通属性、普通方法、构造函数

<font color="red">**子类继承抽象父类的规则**</font>:

- 如果一个<font color="red">**非抽象子类**</font>继承自抽象父类，它必须实现父类中<font color="red">**所有的**</font>抽象方法
- 如果一个<font color="red">**抽象子类**</font>继承自抽象父类，它可以选择性地实现父类的抽象方法。未实现的抽象方法将继续留给它的下一代非抽象子类去实现
