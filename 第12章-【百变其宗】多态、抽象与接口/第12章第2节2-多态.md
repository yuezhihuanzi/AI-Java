## 2.1 什么是多态

想象一下：你对一只动物喊"叫一声",猫会"喵喵",狗会"汪汪",鸟会"啾啾"。同一个指令，不同动物有不同反应——这就是多态！

但为什么是多态？怎么体现出"多"?猫、狗和鸟都是不同的个体，它们发出不同的声音，怎么就是多态了？

这里的关键前提是：猫、狗和鸟都继承自动物。所谓多态，就是调用父类声明的方法(`speak`),但在真正执行时，Java 虚拟机根据对象的实际类型，去调用对应子类的 `speak`,从而产生不同的行为。回顾一下之前学习的"向上转型",你就能理解：动物会根据不同的实际子类，发出不同的声音。

## 2.2 实现多态三部曲

多态的实现需要三个条件，缺一不可：继承关系、方法重写、向上转型。下面逐一来看。

### 继承关系

多态的前提是"一父多子"的继承关系。先定义一个 `Animal` 父类，再让 `Cat`、`Dog` 都继承它：

```java
class Animal {
    void speak() {
        System.out.println("动物发出声音");
    }
}

class Cat extends Animal { /* ... */ }

class Dog extends Animal { /* ... */ }
```

有了这层继承关系，`Cat` 和 `Dog` 才是 `Animal` 的一种，才谈得上"多态"。

### 方法重写

只有继承还不够。`Cat` 和 `Dog` 要发出各自的声音，必须重写父类的 `speak()` 方法，实现自己的个性：

```java
class Cat extends Animal {
    @Override
    void speak() {  // 重写父类方法
        System.out.println("喵喵喵~");
    }
}

class Dog extends Animal {
    @Override
    void speak() {
        System.out.println("汪汪汪!");
    }
}
```

如果不重写，调用 `speak()` 时执行的还是父类的版本，所有动物都只会"动物发出声音",多态就无从谈起。

### 向上转型

最后一步是向上转型：把子类对象赋值给父类引用。

```java
public static void main(String[] args) {
    Animal myPet = new Cat(); // 向上转型
    myPet.speak(); // 输出:喵喵喵~

    myPet = new Dog(); // 同一个引用指向不同对象
    myPet.speak(); // 输出:汪汪汪!
}
```

上面的两处调用，代码一模一样，都是 `myPet.speak()`,但输出的结果完全不同——这就是多态的体现。

多态的核心魔法，其实就在于"向上转型"这一步。

```java
Animal animal = new Cat(); // 把猫当作动物看
```

虽然变量的类型是 `Animal`,但在实际执行时，Java 虚拟机知道它其实是只猫，只是表面看起来是"动物"。所以当执行：

```java
animal.speak();
```

Java 知道要去调用猫的 `speak()` 方法。

## 2.3 多态的优点

其实多态并不难理解，从字面意思就能猜到，"多态"就是"一个类具有多种形态"。猫、狗、鸟都是动物，各有各的样子。但多态真正难理解的是：多态到底有什么用？先给出结论：

<font color="red">**多态可以增强代码的扩展性，降低耦合性。**</font>

但要真正理解这个结论，需要了解一些基本的代码设计思想。

### 消除类型判断

当没有多态时，处理不同动物要靠可怕的类型判断，我们称之为"判断地狱":

```java
// 没有多态的处理方式
public void handleAnimal(Animal animal) {
    if (animal instanceof Cat) {
        ((Cat) animal).speak();
    } else if (animal instanceof Dog) {
        ((Dog) animal).speak();
    } else if (animal instanceof Bird) {
        ((Bird) animal).speak();
    }
    // 每新增一种动物都要修改此处
}
```

多态方案：

```java
// 多态实现
public void handleAnimal(Animal animal) {
    animal.speak(); // 一行代码解决所有动物类型
}
```

代码量减少了 60%～80%,而且新增一种动物类型时，这个方法一行都不用改。

### 开闭原则(OCP)

之前我们讨论过里氏替换原则，这里再讲一个很重要的编程原则：开闭原则。

所谓开闭原则，就是代码应该对新增开放、对修改闭合。需要新增功能时，尽可能不要修改已有代码，而是通过新增代码来实现目标。修改代码很容易造成"改了一处，又带来新的错误",而新增代码出错的概率要小得多。

传统的写法：

```java
// 原始方法
public class Zoo {
    private List<Animal> animals = new ArrayList<>();

    public void addAnimal(String type) {
        if ("cat".equals(type)) {
            animals.add(new Cat());
        } else if ("dog".equals(type)) {
            animals.add(new Dog());
        }
        // 每新增一种动物都需要修改此处
        // 这就违反了开闭原则,是一种不好的做法
    }
}
```

有了多态之后：

```java
public class Zoo {
    // 这是一个泛型,我们目前还没学
    // 可以理解成存储多个对象的List,每个元素都是Animal类型
    private List<Animal> animals = new ArrayList<>();

    // 符合开闭原则的扩展
    public void addAnimal(Animal animal) {
        animals.add(animal);
    }
}
```

当需要新增动物类型时，只需要新增一个企鹅类：

```java
class Penguin extends Animal {
    @Override
    void speak() {
        System.out.println("企鹅叫声:嗷嗷~");
    }
}
```

然后使用：

```java
zoo.addAnimal(new Penguin()); // 无需修改Zoo类
```

仔细观察上述代码：需要新增功能时，最核心的 `Zoo` 类没有做任何修改，只是新增了一个 `Penguin`(企鹅)类。这就符合开闭原则，是一种非常好的代码写法。

当然，初学编程时，可能对开闭原则的重要性理解还不够深刻。没关系，随着代码量的增长，你会越来越注重这些设计方面的规则，它可以大大地提高编码效率，并降低项目成本。
