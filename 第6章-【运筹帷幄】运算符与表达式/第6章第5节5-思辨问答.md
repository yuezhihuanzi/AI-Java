## 5.1 运算符优先级需要背下来吗

**问**：老师，那张优先级表好长啊，需要背下来吗？

**答**：不需要。运算符优先级的学习目的不是为了背诵那张表，而是为了培养一种直觉。

**问**：那学习它的意义是什么？

**答**：三个原因：

**1. 理解表达式的执行顺序**

看到一个复杂表达式时，能大致知道 Java 会如何解析它：

```java
boolean flag = 5 > 3 && 4 < 2 || 3 == 3;
```

你知道关系运算符会先计算，然后是 `&&`，最后是 `||`。

**2. 写出更清晰的代码**

知道何时需要用括号明确优先级：

```java
// 不推荐：依赖优先级，难以阅读
boolean r = a & MASK == FLAG || b < MIN && c > MAX;

// 推荐：用括号明确意图
boolean r = ((a & MASK) == FLAG) || ((b < MIN) && (c > MAX));
```

**3. 避免隐蔽的 bug**

有些优先级陷阱很隐蔽：

```java
int k = 5;
k *= 2 + 3;  // 结果是25，不是13
```

很多人以为 `k *= 2 + 3` 等价于 `k * 2 + 3`，但实际上 `+` 优先级高于 `*=`，所以是 `k * (2 + 3)`。

**问**：那我该怎么记忆？

**答**：只需要记住大致顺序：

- 一元运算符优先级最高（如 `++`、`!`）
- 算术运算符其次（`*` `/` `%` > `+` `-`）
- 关系运算符中等（`>` `<` `==`）
- 逻辑运算符非常低（`&&` > `||`）
- 赋值运算符最低（`=`、`+=`）

> **建议**  
> 实际开发中，遇到不确定的情况，直接用括号明确优先级就好。括号是最安全的做法，也能让代码更易读。

## 5.2 短路机制有什么实际意义

**问**：老师，短路听起来像是性能优化，但真的重要吗？

**答**：短路不只是优化，它更是程序安全的保障。来看几个实际场景。

**场景 1：避免空指针异常**

```java
if (obj != null && obj.getValue() > 0) {
    // 安全访问
}
```

**问**：如果 `obj` 是 `null`，会怎么样？

**答**：如果没有短路，当 `obj` 为 `null` 时，仍然会尝试调用 `obj.getValue()`，直接抛出 `NullPointerException`。但因为 `&&` 短路，当 `obj != null` 为 `false` 时，Java 跳过右侧的 `obj.getValue()`，避免了异常。

**场景 2：性能优化**

```java
if (isCacheHit() || loadFromDatabase()) {
    // 使用数据
}
```

**问**：这里短路的作用是什么？

**答**：如果缓存命中（`isCacheHit` 返回 `true`），`||` 短路会跳过 `loadFromDatabase()`，避免昂贵的数据库查询。这在 Web 应用中很常见。

**场景 3：条件守卫**

```java
if (index >= 0 && index < array.length && array[index] != null) {
    // 安全访问数组元素
}
```

**问**：这里有三个条件，短路怎么工作？

**答**：从左到右，任何一个条件为 `false` 就停止。如果 `index` 是 `-1`，第一个条件失败，后面两个条件都不会执行，避免数组越界异常。

**问**：我明白了。短路的本质是：当结果已经确定时，停止不必要的计算。

**答**：没错。这既是性能优化，也是安全机制。

> **建议**  
> 默认使用 `&&` 和 `||`（短路版本）。只有在特殊场景（如需要确保所有方法都被调用以记录日志）才使用 `&` 和 `|`（非短路版本）。

## 5.3 为什么 && 优先级高于 ||

**问**：老师，`&&` 和 `||` 都是逻辑运算符，为什么 `&&` 优先级更高？

**答**：这与数学逻辑和日常语言习惯有关。

**问**：数学逻辑角度呢？

**答**：在布尔代数中：

- `&&` 对应逻辑「与」（AND）
- `||` 对应逻辑「或」（OR）
- AND 的优先级天然高于 OR

这是数学标准，编程语言遵循了这个约定。

**问**：日常语言角度呢？

**答**：看这个句子：

> A 且 B 或 C

我们通常会理解为：（A 且 B）或 C，而不是 A 且（B 或 C）。

**问**：确实如此！

**答**：Java 也是这个逻辑：

```java
boolean result = a && b || c;
// 等价于 (a && b) || c
// 不是 a && (b || c)
```

**问**：如果我不确定，该怎么办？

**答**：用括号！优先级规则是为了方便理解，不是为了让代码更晦涩。

> **核心原则**  
> <font color="red">**清晰 > 简洁。**</font>如果表达式让人疑惑，就用括号明确优先级。好代码不需要读者去查优先级表。
