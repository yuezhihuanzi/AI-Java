## 5.1 为什么需要 switch-case？if-else if-else 不是已经够用了吗

**问**：老师，既然 if-else if-else 可以处理所有多分支情况，为什么还要有 switch-case？这不是重复造轮子吗？

**答**：好问题！让我问你一个场景：你需要根据用户的输入（1-7）输出对应的星期几，用 if-else 怎么写？

```java
if (day == 1) {
    System.out.println("星期一");
} else if (day == 2) {
    System.out.println("星期二");
} else if (day == 3) {
    System.out.println("星期三");
} else if (day == 4) {
    System.out.println("星期四");
} else if (day == 5) {
    System.out.println("星期五");
} else if (day == 6) {
    System.out.println("星期六");
} else if (day == 7) {
    System.out.println("星期日");
} else {
    System.out.println("无效日期");
}
```

**问**：嗯……确实很冗长。那用 switch 呢？

**答**：

```java
switch (day) {
    case 1 -> System.out.println("星期一");
    case 2 -> System.out.println("星期二");
    case 3 -> System.out.println("星期三");
    case 4 -> System.out.println("星期四");
    case 5 -> System.out.println("星期五");
    case 6 -> System.out.println("星期六");
    case 7 -> System.out.println("星期日");
    default -> System.out.println("无效日期");
}
```

看到区别了吗？if-else 适合<font color="orange">**范围判断**</font>（如 `score>=90`），switch 适合<font color="orange">**精确值匹配**</font>（如 `day==1`）。

关键差异：

- **语义清晰度**：switch 明确表示「从多个固定值中选择一个」，意图更清晰
- **性能优化**：编译器会对 switch 做优化（如跳转表），分支多时比 if-else 快
- **现代 switch 更强大**：可以返回值、支持表达式、自动阻断穿透

但这不意味着 switch 完全替代 if-else。两者互补，各有所长。

## 5.2 switch 的穿透机制是不是设计缺陷

**问**：老师，传统 switch 的穿透（Fall-through）太容易出 bug 了，忘记写 break 就会出错。这是不是 Java 的设计缺陷？为什么不强制要求写 break？

**答**：这确实是个有争议的话题。但穿透不是缺陷，而是<font color="red">**有意设计**</font>。让我给你看一个巧妙利用穿透的例子：

```java
switch (month) {
    case 12:
    case 1:
    case 2:
        System.out.println("冬季");
        break;
    case 3:
    case 4:
    case 5:
        System.out.println("春季");
        break;
    case 6:
    case 7:
    case 8:
        System.out.println("夏季");
        break;
    case 9:
    case 10:
    case 11:
        System.out.println("秋季");
        break;
}
```

**问**：哦！多个 case 共享同一段代码，不用写重复的逻辑？

**答**：对！这就是穿透的价值。如果没有穿透，你需要：

```java
if (month == 12 || month == 1 || month == 2) {
    System.out.println("冬季");
} else if (month == 3 || month == 4 || month == 5) {
    System.out.println("春季");
}
// ...
```

或者更糟：

```java
if (month == 12) System.out.println("冬季");
else if (month == 1) System.out.println("冬季");
else if (month == 2) System.out.println("冬季");
```

穿透的问题是<font color="orange">**容易被误用**</font>，但它的存在让代码在某些场景下更简洁。

现代 Java（14+）用箭头语法 `->` 自动阻断穿透，既保留了传统穿透的能力（用冒号 `:`），又提供了安全的默认行为（用 `->`）。这是最佳的两全方案。

## 5.3 break 和 continue 的选择会影响代码性能吗

**问**：老师，break 和 continue 不就是控制流程吗？选哪个对性能有影响吗？

**答**：影响非常大！让我用一个真实的例子说明：

假设你有一个包含 100 万条用户记录的数组，需要找到第一个 VIP 用户：

```java
// 方案1: 使用break
for (User user : users) {
    if (user.isVip()) {
        System.out.println("找到VIP: " + user.getName());
        break; // 找到后立即退出
    }
}

// 方案2: 错误使用continue
for (User user : users) {
    if (!user.isVip()) continue; // 跳过非VIP
    System.out.println("找到VIP: " + user.getName());
    // 没有break,继续遍历剩余99万个用户!
}
```

**问**：方案 2 会遍历完整个数组，即使第一个用户就是 VIP？

**答**：完全正确！如果 VIP 在第 2 个位置：

- 方案 1：只检查 2 次就退出，耗时约 0.001ms
- 方案 2：检查 100 万次，耗时约 500ms

性能差距<font color="red">**50 万倍**</font>！

这就是为什么理解 break 和 continue 的语义如此重要：

- **break**：「找到目标，无需继续」→ 提前退出，大幅提升性能
- **continue**：「跳过某些，但需要全部检查」→ 遍历完整集合

选择错误的跳转语句，不仅影响代码逻辑，还会导致严重的性能问题。

## 5.4 循环标签在现代编程中还有必要吗

**问**：老师，循环标签（`break outerLoop`）看起来很复杂，现代编程中还会用到吗？

**答**：好问题！循环标签确实是「古老」的特性，但在某些场景下仍然不可替代。让我对比三种跳出嵌套循环的方式：

```java
// 方式1: break标签
public boolean findTarget(int[][] matrix, int target) {
    outer:
    for (int[] row : matrix) {
        for (int val : row) {
            if (val == target) return true;
        }
    }
    return false;
}

// 方式2: return
public void processMatrix(int[][] matrix) {
    for (int[] row : matrix) {
        for (int val : row) {
            if (val < 0) return; // 直接终止方法
        }
    }
    System.out.println("处理完成"); // 不会执行
}

// 方式3: 提取方法
public void findAndProcess(int[][] matrix) {
    int[] result = searchTarget(matrix);
    if (result != null) {
        processResult(result);
    }
}
```

**问**：这三种方式各有什么优缺点？

**答**：

- **break 标签**：适合「退出循环但继续方法执行」。缺点是语法复杂，可读性差。
- **return**：最简洁，适合「找到结果直接返回」。缺点是无法执行循环后的代码。
- **提取方法**：最优雅，符合单一职责原则。推荐优先使用。

现代编程的趋势是<font color="orange">**减少使用 break 标签**</font>，因为：

1. 方法提取让代码更模块化
2. return 更简洁直观
3. 标签增加了代码的理解成本

但 break 标签并非过时，在某些算法题或性能敏感场景中仍然是最佳选择。关键是理解它的语义，而非盲目使用。

## 5.5 为什么 do-while 在实际开发中很少见到

**问**：老师，我看了很多开源项目的代码，发现 while 和 for 很常见，但 do-while 几乎没见过。是不是 do-while 没用？

**答**：do-while 确实使用频率较低，但这不意味着它没用，而是它的<font color="red">**适用场景比较特殊**</font>。

do-while 的核心特性是「至少执行一次」，这决定了它的使用场景：

**场景 1：用户菜单**

```java
int choice;
do {
    System.out.println("1. 登录");
    System.out.println("2. 注册");
    System.out.println("0. 退出");
    choice = scanner.nextInt();
    
    switch (choice) {
        case 1 -> login();
        case 2 -> register();
        case 0 -> System.out.println("再见");
    }
} while (choice != 0);
```

菜单至少要显示一次，然后根据用户选择决定是否继续。这是 do-while 最典型的应用。

**场景 2：输入验证**

```java
String input;
do {
    System.out.print("请输入邮箱: ");
    input = scanner.nextLine();
} while (!isValidEmail(input));
```

至少请求一次输入，然后验证是否合法，不合法继续请求。

**为什么很少见到？**

1. **while 可以替代**：大多数 do-while 可以用 while 替代（虽然代码稍复杂）
2. **现代框架封装**：GUI 框架、Web 框架已经封装了菜单和输入验证
3. **场景有限**：确实「至少执行一次」的场景不多

但这不意味着 do-while 过时。当你遇到「先执行后判断」的场景时，do-while 仍然是最优雅的选择。
